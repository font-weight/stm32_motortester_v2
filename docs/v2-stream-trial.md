# V2-05: ограниченный опыт транспорта на подключённой плате

Это порядок диагностического опыта с пустым PA0, а не приёмка измерения
напряжения, частоты дискретизации, отсутствия потерь или аналогового входа.
Фактические результаты сохраняются только в `progress.md` и отчётах критика.

## Конкретный образ и возврат

- Исходная опубликованная база: `c10884fa39ad1a10ce0fcfc9d6e17f170e1e0bf0`.
- Образ V2S1: `build/v5-fw-04/MotortesterV2-stream-candidate.bin`, 33764 байта,
  SHA256 `dbc34181ecefc39b9799c6b5c9d4e103478e36ef42bf5e56a209c75e04f96665`.
- ELF: SHA256 `a2a22017e57c0709ac46d1b695acfb9dbc9f9e30d99ee725eeb45c85e271eaa9`.
- Проверенная область возврата: первые 65536 байт Flash,
  `build/v5-board-backup-20261020/window-working-read1.bin`,
  SHA256 `72520303cd27bac89b9cd11d93ef751f0ec30617c1a90dc0427c7ba6a7665d39`.
- Два сохранённых полных чтения 131072 байт совпадают:
  SHA256 `de8bb5f4c8b67c5d31fe74755733f3c852e3945237e3e49a74ebdaaa577a97d5`.
  Верхние 64 КиБ пусты и новым образом не используются.

Перед записью требуется независимый допуск именно этих файлов:
`docs/reviews/v2-05-transport-admission.md`. Допуск не подменяет последующую
аппаратную проверку. Устройство сообщило 128 КиБ Flash, но сборка ограничена
64 КиБ Flash и 20 КиБ RAM; маркировка и подлинность MCU этим не доказаны.

## Условия

По сообщению пользователя PA0/A0 пустой, питание только от USB платы.
ST-Link подключён к той же плате; его 3,3 В не подключены. Не менять проводку,
не подключать датчик зажигания. Приложение и другой владелец COM должны быть
закрыты. Все команды относятся к единственному проверенному ST-Link `ID=0`.
Если обнаружено другое устройство или нет совпадения образа, остановиться.

Предположение конфигурации HSE 8 МГц согласуется с прежней рабочей прошивкой
и регистрами, но внешним прибором не измерено. 50 kS/s пока номинальны.

## Загрузка, проверка и короткий приём

1. Проверить SHA256 образа и резервной копии непосредственно перед записью.
   Сохранить вывод ST-Link Utility CLI 3.6.0.0. Использовать
   `-c ID=0 SWD HOTPLUG -P <BIN> 0x08000000 -V after_programming`.
   Не использовать mass erase, изменение option bytes или защиту чтения.
   Обычное программирование стирает необходимые страницы.
2. Отдельно прочитать ровно 33764 байта (`0x83e4`) от `0x08000000`;
   SHA256 должен совпасть с BIN. Это доказательство загруженного образа,
   тогда как HELLO build ID сам по себе такой проверкой не является.
   Остаток старого образа за новой программой не объявлять частью нового
   образа; весь первый 64 КиБ восстанавливается резервной копией при откате.
3. Выполнить обычный `-Rst -Run`. При устаревшем состоянии USB попросить
   пользователя переподключить только USB платы. Порт определить заново.
4. Запустить `host/tools/v2_stream_probe.py` с явно указанным COM, build ID
   `0x56325331`, SHA образа и исходным commit; отдельный новый каталог опыта.
   Connect отправляет только HELLO/GET_CAPS. При несовпадении ID START
   запрещён. После ответа — Start, запись 15 секунд, Stop, fresh Open,
   закрытие владельца порта. Сохранить весь обмен, исходный `.mtstream`,
   companion и результаты. Увеличение индексов, проверка CRC и чтение файла
   не означают доказанного отсутствия пропущенных преобразований АЦП.
5. В течение приёма не останавливать ядро отладчиком и не читать RAM.
   После Stop/закрытия снять два последовательных чтения 136 байт
   `mt_stream_diagnostics` по `0x2000238c` из данного ELF. Сохранить оба,
   проверить стабильность, декодировать по заголовку той же базы.
   Диагностика DWT ограничена 32-битным счётчиком (~59,65 с при номинальных
   72 МГц); наблюдаемый максимум не объявлять универсальным WCET.
6. Нормальный END этой базы имеет неизвестный итог произведённых отсчётов.
   Сохранить неизвестный хвост и обозначение неполных данных. Не превращать
   штатный Stop в обещание нулевых потерь.
7. После успешного короткого опыта отдельно проверить отключение USB во
   время записи с участием пользователя: сохранить доступный префикс,
   отсутствие END и возможность открыть файл. Не имитировать физический
   результат синтетическим транспортом.

## При отказе и возврат

Не повторять START автоматически. Сначала сохранить обмен, файл, ошибки и,
если возможно без потери сведений, диагностику. Закрыть COM. Если образ
не запускается, идентичность не подтверждена или продолжение требует
неготового исправления, вернуть рабочую оконную копию:

1. `-c ID=0 SWD HOTPLUG -P <window-working-read1.bin> 0x08000000 -V after_programming`.
2. Прочитать 65536 байт отдельно, сверить SHA с резервной копией.
3. `-Rst -Run`; при необходимости переподключить USB платы.
4. Проверить прежний HELLO/GET_CAPS wire 0.1 без CONFIG/ARM/START.

Если невозможно связаться по SWD, не менять option bytes или питание
автоматически: сохранить ошибку и уточнить физическое соединение.
Неудачный опыт и новая прошивка сохраняются независимо от отката.
