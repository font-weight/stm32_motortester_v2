# V2-06l — проект DATA1024 при150k

25.10.2026. Проект для реализации; приёмка кода и аппаратных опытов отдельно.
Требование V2-STR17. База SD/sourcecb475794; код репозитория перед L —
bbe297e584d4cb5f22bd090980f721aaa933233a. Результаты только в progress.

## Границы и размер

Один непрерывный CH1, физический ADC12, передача10MSB с явной потерей2LSB.
Новый mode5/config5, wire0.3, неизменные header24 + DATA metadata20 +
packed ceil(10N/8) + CRC4. Для1024: payload1300/raw1328/COBS сdelimiter
не более1335. Allocation TX1336 отдельно от RX/previous543; глобальное
расширение firmware FRAME_MAX запрещено. Старые modes1..4 и их архивы
сохраняют прежние границы. Footer/wire0.4 не вводится.

1024 при150k —6,826667мс, DATA146,484375/с; worst wire195556,640625байт/с
вместо217382,8125 для256. Это расчёт объёма, не гарантия USB throughput.
Предельный2048байтный canonical блок у host остаётся в домене ADC12,
code=(ADC12>>2)<<2. UI имя/профиль не меняют калибровку a*code+b.

## Накопление и владение

Нельзя ждать заполнения всех8 queue128 и удерживать их до полной USB
передачи. Проект: постепенно упаковывать подтверждённые128-блоки в отдельную
область существующего увеличенного TX; после проверки переносить владение
в staging и освобождать очередь. Точный source-index интервал staging
хранится отдельно от переданного prefix. Потеря staging не считается
успешной передачей. Размер очереди/DMA, таймер150k и аналоговый вход прежние.

Число отсчётов известно ДО первого отправленного байта: полный1024 либо
последний короткий при Stop. Нельзя дополнять нулями или ждать новых ADC
после quiesce. Подготовка заголовка, CRC и COBS — ограниченными порциями
без большого локального массива и без длительного запрета IRQ. In-place
COBS использует зарезервированный запас начала TX, сохраняя непрочитанный
raw. Прототип обязан проверить длинные ненулевые серии/нули/границу254,
все остатки packed10 и конечные хвосты.

Подготовленный кадр поступает в FIFO частями<=384 с сохранением порядка.
Между частями обслуживаются ADC/TIME/USB/команды. Только полностью принятый
кадр продвигает опубликованный prefix и rolling canonical CRC. Known0 не
продвигает offset, short known продвигает только принятые байты; unknown,
смена epoch/nonce и повреждение времени не разрешают ложный commit.
Stop/HELLO/обрыв во всех стадиях collection/encode/send требуют отдельной
проверки: не смешивать сеансы, не объявлять частичный кадр завершённым,
не включать staging потерянного сеанса в следующий. Для production сохраняются
Stop/HELLO500мс и transaction bound1мс; ownership и deferred final commit
определены [проектом r2](verification/v2-batch1024/planning-01/integration-plan-r2.md).
Модуль сам по себе не доказывает соблюдение временных границ на плате.

## Память и проверка до интеграции

SD: точное основание — static-bound K: data128+bss11244+
8192reserve=19564, запас916байт из20КиБ. TX544→1336 добавляет792,
остаётся124 на состояние/выравнивание при сохранённом резерве.
Предлагаемый state32 даёт расчёт20388/20480, запас92; это ещё не ARM map. Не увеличивать
одновременно rx/previous и не выделять mt_wire_message1300/raw1328 на стеке.
Прототип должен предъявить sizeof state и bounded work; окончательные
SRAM/stack/Flash проверяются отдельной ARM-сборкой всего приложения.
Существующий8192 reserve не является измеренным пиком стека.

## Согласование и host

Discovery HELLO0.2 принимает только(cap,maxblock,maxpayload):
(1,128,512),(3,128,512),(7,256,512),(15,1024,1300).
После15 — другая свежая nonce HELLO0.3 с mode1/2/5. Selected ACK cap1:
128/512 для1..3,256/512 для4,1024/1300 для5. CAPS mode5 строго
(5,5,0,12,150000,1,1024,1,10,2). Public150 требуетmode5; наSC/SD отказ
доSTART с понятным сообщением, без скрытого fallback. Историческийmode4
остаётся доступен для чтения файлов и точных старых инструментов.

Большой envelope допустим только device DATA0.3/config5; старые режимы и
controls сохраняют payload<=512/frame<=544. Host read544 остаётся прежним:
аккумулятор собирает один frame<=1335 из нескольких чтений. CRC/delimiter,
nonce/gen/config/index/count/padding проверяются до публикации samples.
Последний short1..1023 допустим только в конце, DATA после short запрещён.

Intrinsic marker 0.3-batch1024-20261025 + mode/config5; Fs150000,
source12/retained10/discarded2/u10packed_le/left_shift_2/truncate_lsb,
stored u16le/adc12.17полей и magic3/4/companion3 прежние, расширение enum
строгое. Без companion формат и время20/3мкс сохраняются. Raw cap256КиБ,
items1024, journalchunk8192 прежние; CSV помечает retained10.

## Предлагаемые правила интеграции (ещё не реализованы)

- COLLECT и очередь — два последовательных интервала. Queue.pop переносит
  владение в staging, не подтверждает доставку. END допустим только когда
  hardware_off подтверждён, очередь пуста, staging пуст и нет незавершённого TX.
- Stop синхронно quiesce/сертифицирует хвост; retained очередь достраивает
  текущий пакет.1024 отправляется полным, последний1..1023 коротким; после
  короткого DATA только END. При queue fault поздний хвост не склеивается
  через потерянный блок; причина1 остаётся даже при успешной отправке prefix.
- Replacement HELLO: ещё не отправленный staging можно отбросить вместе
  со старым сеансом (он не был принят host). Уже частично отправленный
  immutable DATA заканчивается под старой identity либо barrier+delimiter
  явно обрывает старый кадр. Новый nonce не может дописать старый staging.
  Выбор exact ветви должен совпасть с существующим lifecycle перед сборкой.
- In-place COBS изменяет storage необратимо: после stale epoch/TIME нельзя
  восстановить только старую копию state и повторить работу. Весь такой
  in-flight кадр инвалидируется; при принятых байтах нужен delimiter/barrier.
- Canonical CRC вычисляется заранее по тем же значениям, что packed bytes.
  Commit после последнего известного принятого байта и final guards сверяет
  seed/first_index/current prefix, затем публикует end/CRC без длинного CRC
  внутри PRIMASK. Это условие caller, serializer не доказывает runtime guard.
- Quantum512 — предел отдельного шага прототипа, не обязательный новый
  полный runtime loop на каждую порцию. Scheduler должен обслуживать ADC
  до его deadline и не вводить12 дорогих loop/packet без оценки throughput.
  Exact ARM/static и физический замер нужны до утверждения ускорения.

## Приёмка

Один адресный native прототип packing/CRC/in-placeCOBS/partial send/tails,
его fixture→host; targeted host negotiation/limits/file compatibility.
Далее независимый критик точного состояния. До интеграции production
обязательны конкретные lifecycle/epoch/Stop invariants и статический budget;
до Flash — точная сборка/пакет и отдельный план с backup/readback.
Физический минимум stable150k — ограниченный30с опыт без queue fault,
нормальный END/ACK, wire/raw/Open/CRC и остановленная периферия; это ещё
не долговременная квалификация.50/100 регрессии не исчезают из очереди.
SD не откатывается автоматически. Сейчас новый образ не записывался.
