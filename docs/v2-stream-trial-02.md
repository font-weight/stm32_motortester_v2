# V2-05: повторный ограниченный опыт с V2S2

Это новый план после сохранённого неудачного опыта V2S1. Условия, методика
и возврат из [первого плана](v2-stream-trial.md) сохраняются; разрешение
первого образа не переносится на этот BIN. До записи нужен отдельный
`docs/reviews/v2-05-transport-admission-02.md` с точными хешами.

## Предмет

- База `c10884fa39ad1a10ce0fcfc9d6e17f170e1e0bf0`, новый V2 patch-chain
  `firmware/v2-stream/overlays/usb-nvic.json`; recipe/inputs —
  `build/v5-fw-07/receipt.json`.
- BIN `build/v5-fw-07/MotortesterV2-stream-candidate.bin`,
  **34028 байт / 0x84EC**, SHA256
  `0298ce70716b9d9282e575291c627e271a57bedca501989d027b3fc045b6ba1e`.
- ELF SHA256
  `fd5377b631128daac217e5b624f931b65c85c1ed7f6e41fca6ca8110f1d00cac`.
- Наблюдаемый build ID должен быть **0x56325332 / V2S2**.
- Единственное инженерное изменение — ограничение повторных USB IRQ
  через NVIC с отдельным обслуживанием lifecycle. TIME32ms, Stop,
  ADC и epoch-проверки не ослаблены. Аппаратная причина первого отказа
  ещё требует проверки: исправлен дефект, способный его вызвать.

## Последовательность

1. Проверить, что подключён прежний единственный ST-Link
   `57005400120000393333574E`; A0 остаётся пустым, питание только USB платы.
   Закрыть владельцев COM. Сверить SHA нового BIN и старой 65536-байтной
   копии `build/v5-board-backup-20261020/window-working-read1.bin`.
   Её SHA — `72520303cd27bac89b9cd11d93ef751f0ec30617c1a90dc0427c7ba6a7665d39`.
2. После независимого допуска: программирование на `0x08000000` через
   ST-Link `-P ... -V after_programming`, без mass erase/option bytes.
   Отдельный `-Dump 0x08000000 0x84EC ...`; сравнить длину и SHA с BIN.
3. System `-Rst -Run`, затем переподключение USB платы пользователем, чтобы
   Windows заново перечислила устройство. Не обращаться SWD к работающему
   захвату. Сохранить фактический COM.
4. Один запуск `host/tools/v2_stream_probe.py`: явные port/build/hash/base,
   новый каталог `build/v5-board-stream-02/run`, 15 секунд записи.
   HELLO/CAPS без START, проверка ID, Start → Record → Stop → fresh Open →
   закрытие владельцев. Никакого автоматического повторного START.
5. `host/tools/verify_stream_trial.py` сопоставляет DATA из сохранённого
   обмена и raw выбранного диапазона файла побайтно, проверяет последовательность,
   CRC и END/STOP_ACK. Это равенство доставленных байтов, а не no-loss ADC.
6. После остановки снять два чтения 136 байт по **0x2000238c**.
   Декодировать `decode_stream_diag.py` из исходной базы с фактическими
   generation/nonce из wire-verification, build `0x56325332`.
   Замороженность признавать только при совпадении дампов, magic/version/bytes,
   phase=3, hardware_off=1, adc_owned=0 и ADC STOPPED. Время номинальное;
   DWT-метрики не доказывают универсальный WCET или точность Fs.
7. После успешного опыта — отдельный system reset перед проверкой USB-обрыва,
   поскольку диагностический record фиксирует только первый сеанс за boot.
   Пользователь отключает USB во время записи по согласованному сигналу.
   Проверить сохранение префикса/unknown tail и fresh Open; сохранить обмен.
   После опыта вернуть питание USB и оставить плату в готовом состоянии.

## Отказ и возврат

До START при ошибке перечисления/времени сохранить PnP и RAM без изменения
состояния программы командами отладчика; после отказа в записи сохранить
raw/обмен/диагностику. В данном ELF main_last_runtime=0x20000478,
usb_init=0x2000047c, irq_admitted=0x20000480, boot_failure=0x20000484;
не использовать прежние адреса main-переменных V2S1.

Если продолжение требует ещё не проверенного исправления, вернуть старую
65536-байтную копию через `-P ... 0x08000000 -V after_programming`,
отдельно прочитать `0x10000` байт и сверить SHA, выполнить Reset/Run и
переподключение USB, проверить прежний wire 0.1 HELLO/CAPS без захвата.
Не стирать неудачные материалы и не маскировать отказ перезапуском.
При недоступности SWD сохранить ошибку и уточнить физическое подключение.
