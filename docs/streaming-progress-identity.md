# Общий build id для прошивки и диагностического наблюдателя

Причина P — доказанный отказ64B observer в SH: его независимая константа
осталась от SG и не совпала с legacy136. Это запрещало инициализацию записи.
Нулевой банк означает отсутствие пригодного замера, а не нулевую нагрузку.
Исходный опыт и его оценки сохраняются в [progress](progress.md).

Единственный числовой источник — `firmware/v2-stream/config.json`.
После проверки конфигурации сборка создаёт общий header с build id;
сгенерированный board descriptor и observer используют это определение.
При отсутствии определения сборка observer должна завершиться ошибкой.
Нельзя подставлять старый ID по умолчанию или обновлять вторую константу вручную.
Nonce/generation и прежние admission/freeze проверки остаются обязательными.

Кандидат SI сохраняет расписание SH, wire и размер пакета1024. У наблюдателя
нет новой постоянной памяти, его ABI64 и отдельная legacy136 сохраняются.
Исправленный observer снова выполняет свою диагностическую работу: его
влияние на быстродействие нельзя исключать из последующего опыта.

Адресная native-проверка исполняет actual C observer с header из exact ARM
сборки. Правильный SI build должен запустить запись и сохранить freeze;
старые SG/SH identity должны быть отвергнуты. Полученные C64/136 fixture
используются offline decoder. Native legacy setup и часы остаются моделью,
не измерениями платы. Decoder требует явного `--build-id 0x56325349` и
согласованной identity; SG сохраняется default для исторических файлов.

Программная проверка относится к исправлению измерителя. Следующий physical
опыт допускается отдельным exact планом после независимого review; он должен
проверить действительное заполнение64B и по возможности дать first-close
данные для разбора queue-full. Повторы и откат не автоматические.
Устойчивые150k требуют отдельного фактического успеха; исправный снимок
диагностики сам по себе эту цель не закрывает.
