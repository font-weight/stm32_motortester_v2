# V2-03 — подключение STM32 и оконный захват

Этот документ задаёт технический контракт и порядок работы. Фактические порты, ответы конкретного устройства, проверки, версия EXE и итог приёмки записываются в [progress.md](progress.md). Наличие инструкции не означает, что описанный путь уже проверен на плате. V2-01/02 с DEMO и файлами сохраняются.

## Выбранная совместимость

Используется существующий **оконный wire 0.1** и адаптер [device.py](../host/motortester/v2/device.py) над [AcquisitionBridge](../host/motortester/acquisition.py). Отдельный рабочий поток, владение принятыми окнами, Stop-барьеры, восстановление после ошибки и закрытие порта остаются у прежнего компонента.

Состав исходников для проверки выбран по опубликованному снимку исходного проекта [96002ce62bb5c065ac665ca81059c4a62e90d1dd](https://github.com/font-weight/stm32_motortester/commit/96002ce62bb5c065ac665ca81059c4a62e90d1dd):

| Область | Git tree, совпадающий с локальной базой V2 |
|---|---|
| `firmware/` | `4b9307f874610a03ccb38e557ed9f0f6eeb94c1e` |
| `protocol/` | `91311856082ea6a6b32b06c2a060c2564af010d0` |

Это идентичность **исходных файлов**, не подтверждение загруженного в плату бинарника. `firmware_build` из HELLO_ACK — объявленный номер сборки, не SHA образа, не идентификатор экземпляра MCU и не доказательство его маркировки. VID/PID, USB serial и COM помогают выбрать устройство, но не устанавливают эти свойства. Номер COM может меняться.

Потоковый [PR #216](https://github.com/font-weight/stm32_motortester/pull/216), `c10884fa39ad1a10ce0fcfc9d6e17f170e1e0bf0`, относится к отдельному wire 0.2. Его прошивка не импортируется и не прошивается в рамках V2-03. Оконный wire 0.1 нельзя объявить непрерывным потоком из-за наличия host stream-модулей.

**Известная граница аудита:** в [mt_control.c](../firmware/app/mt_control.c), строки 188–192 выбранного снимка, обработка `parsed != MT_COMMAND_OK` отвечает ERROR до проверки `MT_LINK_STOPPING`. Текст [wire-v0.1.md](../protocol/wire-v0.1.md) требует приоритета восстановления при действующем Stop-барьере также для UNKNOWN_TYPE/INVALID_PAYLOAD. Поэтому полная совместимость реализации со всем текстом протокола не заявляется. V2 использует корректные сериализованные команды и сохраняет запрет обычных запросов во время Stop; известный ошибочный путь он намеренно не отправляет. Это ограничение не скрывается за успешным HELLO/CAPS.

## Подключение не запускает измерение

1. Пользователь выбирает физический источник и **явно указывает COM-порт** в панели «STM32 · подключение». Перечень портов только перечисляет устройства; не открывает и не опрашивает их автоматически.
2. Кнопка подключения открывает выбранный порт и выполняет HELLO → HELLO_ACK → GET_CAPS → CAPS. На этом шаге нет CONFIG/ARM и запуска захвата.
3. UI показывает фазу соединения, принятые возможности и объявленную сборку. Состояние READY означает готовность согласованного host-сеанса к отдельной команде; оно не заменяет независимое измерение аппаратуры.
4. Старт становится доступен только после согласованных текущих HELLO/CAPS. Неподдерживаемая версия, противоречивые возможности, ошибка транспорта или необходимость восстановления блокируют запуск.

Старый CAPS не сохраняет действительность после потери соединения. Подтверждение физического сброса не ставится программой автоматически: открытие COM-порта не доказывает reset. Если рабочий компонент требует сброс перед повторным подключением, пользователь действительно выполняет сброс/переподключение и затем подтверждает это в панели.

## Доступные команды и настройки

| Управление | Смысл в V2-03 |
|---|---|
| Auto | Отдельный CONFIG/ARM, повторяемые **окна**, каждое со своей границей; при отсутствии запуска возможен Auto timeout с соответствующим флагом |
| Single | Отдельный CONFIG/ARM для одного окна; ожидание фронта само по себе не ошибка передачи |
| Stop | Явная остановка через существующий барьер; сообщение об успехе требует подтверждённого результата, при ошибке — восстановление |
| Порог | **Исходный код ADC 1…4094**, не вольты на CH1; задаётся в панели устройства |
| Фронт | Рост/спад исходного кода; при неизвестном аналоговом тракте это ещё не подтверждённая полярность U_CH1 |
| Предыстория | Только из текущих CAPS: 0/512/1024 отсчёта — 0/25/50% окна 2048 отсчёта; неподдерживаемые варианты недоступны |
| Пауза запуска | Аппаратной команды holdoff в wire 0.1 нет; DEMO-регулятор не имитирует её |
| Record | Непрерывная запись для устройства **недоступна** в этой итерации; сохраняется одно полное окно |

Для выбранного профиля 1 данные имеют один канал, 12-битные коды 0…4095 и 2048 отсчётов в окне. Частота выводится из объявленных таймерных параметров; для 72 МГц, PSC=71, ARR=19 это **номинальные 50 кГц**, не измеренная частота. Auto timeout выбран адаптером 1000 мс, Single использует 0; это не настройка holdoff и не пауза просмотра. Остальные возможности firmware не становятся функциями V2 автоматически.

Четыре регулятора масштаба/положения относятся к просмотру. Изменение развёртки не меняет частоту ADC или размер аппаратного окна. Пауза просмотра не Stop; перед сохранением выбранного аппаратного окна следует остановить повторный захват или выбрать Single.

## Неизвестная шкала и служебный просмотр

Физический источник получает `UNKNOWN_PROFILE`: `state=unconfigured`, без `a/b`. Основное сообщение — **«Шкала напряжения не настроена»**. Ни номинальные 3,3 В, ни DEMO-профиль не подставляются на CH1. Известные ADC bits и profile=1 не раскрывают усиление, смещение, Vref, coupling и калибровку реального входа.

Для проверки доставки отсчётов пользователь отдельно включает явно подписанный **служебный просмотр кодов ADC**. Тогда ось/амплитуда/порог относятся к кодам; В/мВ и ΔU недоступны. Это диагностическое исключение для unconfigured, а не замена основной шкалы продукта. Возврат к DEMO восстанавливает его отдельный синтетический профиль.

Без знания тракта нельзя сделать вывод о напряжении на разъёме по raw-кривой. Настройка и калибровка входа — отдельный следующий шаг по [hardware-input.md](hardware-input.md); они не выполняются переименованием CH1 или выбором «Осциллограф / Зажигание».

## Сохранение данных и времени

Полное окно принимается существующим runtime только после согласованного WINDOW_BEGIN/DATA/END, допустимых индексов/кодов и CRC. Оно преобразуется в одну V2-запись с исходными отсчётами, `source=device`, снимком `UNKNOWN_PROFILE`, аппаратным raw-порогом, параметрами запуска и объявленными версиями. Время окна начинается с локального индекса 0; `time_basis=nominal_unverified`, флаги `window_local_time` и `interwindow_timing_unknown`.

**Время между окнами неизвестно.** Время получения на ПК не определяет непрерывную временную шкалу ADC. Несколько окон не склеиваются, промежуток не заменяется нулём, соседняя кривая не дорисовывается. Непрерывный Record потребует отдельного сегментного формата и доказанного временного контракта.

Сохранить можно одно полное окно как `.mtv2` и экспортировать CSV + `.csv.json`. Исходный код сохраняется; `voltage_v` пустое, напряжения в анализе неизвестны. Повторное открытие не присваивает глобальную DEMO-калибровку. Контракт основного файла — [v2-format.md](../host/docs/v2-format.md).

Неполный или не прошедший семантическую проверку результат сохраняется отдельно: диагностический JSON `format=motortester-v2-incomplete-report`, `format_version=1`, `complete_recording=false`. В нём доступны полученные фрагменты с их offset, отсутствующие диапазоны/причина, сведения текущего сеанса и неизвестный профиль. Это не полноценная `.mtv2`-запись и не свидетельство отсутствия сигнала; пропуски не заполняются нулями.

## Закрытие с незавершённым окном — V2-03a

При запросе закрытия и наличии несохранённого неполного окна приложение предлагает три действия:

- **«Сохранить JSON»** — выбрать файл и сохранить диагностические фрагменты. Успех позволяет продолжить закрытие; отмена выбора файла или ошибка записи оставляет приложение открытым и данные в памяти.
- **«Закрыть без JSON»** — явно отказаться от сохранения именно показанного неполного окна. Эти несохранённые фрагменты будут потеряны.
- **«Отмена»** — оставить приложение открытым и сохранить неполные данные в памяти. Это выбор по умолчанию; закрытие самого диалога имеет тот же смысл.

Решение относится к конкретному ожидающему окну: другое окно, появившееся во время диалога или сохранения, не удаляется по прежнему согласию. Уже сохранённая `.mtv2` и полные записи не меняются. Согласие закрыть без JSON не обходит подтверждение Stop, восстановление после ошибки или проверку завершения рабочего потока. Сохранение диагностического отчёта также не является доказательством успешного Stop.

Этот раздел задаёт контракт исправления; проверенные версии исходников/EXE и результаты — только в [progress.md](progress.md). Изменение не добавляет аппаратных измерений или калибровки.

## Первый сценарий для пользователя

Использовать только уже существующее подключение платы; **не подключать новый внешний сигнал** в рамках проверки связи.

1. Выбрать физический источник — четвёртый пункт списка; открыть панель «STM32 · подключение».
2. Выбрать свой COM и нажать подключение. Сначала посмотреть READY, версию и CAPS. До отдельного старта окно не захватывается.
3. При неизвестной шкале включить служебный просмотр кодов. Нажать Auto, дождаться окна и нажать Stop; Auto может получить окно по таймауту с явной отметкой. Single пригоден, когда ожидается подходящий фронт; ожидание можно завершить Stop.
4. Сохранить одно полное окно `.mtv2`, открыть его повторно и при необходимости экспортировать CSV. Неполные фрагменты можно сохранить отдельным диагностическим JSON; при закрытии доступен явный выбор, описанный выше.
5. Нажать отключение и выбрать DEMO-источник, чтобы вернуться к прежним примерам. Не считать закрытое окно приложения подтверждением успешного Stop, если отображается ошибка закрытия/соединения.

Вопросы, требующие следующего этапа: идентичность реально прошитого образа, допустимый DC-вход, коэффициенты и калибровка, измеренная частота/полоса, физическая форма сигнала. Программное ревью и даже приём одного raw-окна этих вопросов не закрывают.
