# V2-20 — частота найденных событий

**«Частота событий»** показывает, как часто программа находит пороговые
события в текущем живом потоке. Она использует недавнюю историю найденных
событий, а не только импульсы, помещающиеся на экране. Во время приёма
строка подписана **«Частота событий (живой приём)»**.

Поэтому при крупном масштабе можно видеть один импульс и одновременно
получать частоту событий по нескольким предыдущим импульсам. Если во всём
доступном потоке пока найдено только одно событие, данных для такой оценки
недостаточно. Требуется не менее трёх подходящих событий. Оценка берёт
медианный интервал из последних 2–8 интервалов; существенно различающиеся
интервалы получают сообщение **«Интервалы событий нерегулярны»**.
Причина отсутствия числа показывается в самой строке.

## Как пользоваться

1. Перед запуском задайте **«Уровень запуска»** так, чтобы нужные импульсы
   пересекали порог в выбранном направлении. **«Пауза запуска»** задаёт
   минимальный интервал между началами найденных событий; слишком большая
   пауза может подавлять следующие импульсы.
2. Нажмите **«Применить поиск»**, затем **«Живой поток»**. Дождитесь нескольких
   найденных событий. Параметры поиска относятся к этому приёму и сами по
   себе не изменяют физический сигнал или работу АЦП.
3. При необходимости включите **«Синхронизация по событию · порог в центре»**.
   Это удерживает положение импульса на графике. История для строки
   **«Частота событий»** продолжает накапливаться независимо от масштаба.
4. **«Пауза просмотра»**, курсоры и просмотр удержанного события не
   останавливают приём. Частота событий относится к продолжающемуся живому
   приёму; показатели видимого участка при этом относятся к удержанному графику.

После **«Остановить»**, открытия файла, смены источника или переподключения
прежнее живое значение не переносится в новый контекст. Новый запуск
должен накопить собственную историю. Открытая запись сохраняет показатели
своего видимого участка; эта строка предназначена для живого приёма.

## Чем отличается от периода видимого участка

**Период / Частота** среди [измерений видимого участка](segment-measurements.md)
проверяет повторяемость исходной формы именно на экране. Для неё нужны
несколько полных циклов. **«Частота событий»** опирается на моменты срабатывания
настроенного порогового поиска в живой истории. Эти показатели отвечают
на разные вопросы и могут иметь разные причины недоступности.

Крайние коды АЦП могут сопровождаться предупреждением о возможном ограничении.
Само это предупреждение не запрещает оценивать интервалы между найденными
событиями. Однако ограничение может искажать форму и влиять на обнаружение
событий. Пропуски данных, недостаточная история, отсутствие свежих событий
или непригодные интервалы получают отдельное объяснение вместо числа.

Пороговое событие не является доказательством искры, номером цилиндра
или оборотом двигателя. **«Частота событий»** не показывает RPM и не
подтверждает исправность зажигания. Результат зависит от порога, направления,
гистерезиса и паузы; несколько колебаний одного импульса могут повлиять
на поиск. Время опирается на частоту дискретизации исходника, без объявления
её физически измеренной.

Для программной проверки без платы используйте **«Сервис → ДЕМО для проверки
→ Зажигание»**. Уменьшите видимый интервал до одного импульса: строка частоты
событий продолжает использовать живую историю, а оценка периода видимого
участка может сообщать о нехватке повторений. Это проверка интерфейса
на искусственных данных, не измерение реальной платы.

Актуальный запуск — в [README](../README.md). Фактические проверки конкретной
сборки и её ограничения — в [прогрессе](progress.md).
