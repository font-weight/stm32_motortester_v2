# M: сократить вычисления при подготовке DATA1024

Этот ограниченный шаг продолжает требования V2-STR14/V2-STR17 и
[контракт DATA1024](streaming-batch1024.md). Текущий статус и фактические
проверки находятся только в [progress](progress.md) и отчёте критика.

## Основание и выбранное изменение

В SE последний проход подготовки может одновременно обработать512 кодов,
посчитать CRC по1324 байтам и закодировать1328 байт COBS. Шесть внутренних
шагов по512 байт выполняются внутри одного вызова; АЦП между ними не
обслуживается. Счётчик guarded-TX начинается после этой подготовки.
Его максимум нельзя вычитать из отдельного максимума runtime для измерения
стоимости подготовки. Сохранённая диагностика L2 не устанавливает, какая
часть работы единолично вызвала переполнение.

В скомпилированном SE байтовые циклы CRC/COBS многократно читают и сохраняют
счётчики и CRC в структуре состояния. M переносит эти величины в локальные
переменные одного синхронного шага и сохраняет состояние при выходе из него.
Это даёт компилятору возможность держать их в регистрах, не добавляя буфер.
Не вводить новый `restrict`-контракт. Прежние state/storage не пересекаются,
ISR не использует промежуточное состояние serializer.

## Обязательная эквивалентность

- Тот же порядок байт, canonical-prefix CRC, frame CRC, COBS и delimiter.
- Тот же бюджет1…512, переходы фаз и возвращаемое число обработанных байт.
- Точные state и storage на каждом возврате, включая defensive error после
  уже выполненных in-place записей. Нельзя откатить только state, оставив
  изменённые байты скрытыми от следующего вызова.
- Прежние проверки перед записью, shared-byte retry при collection,
  deferred commit только после известного полного приёма и final TIME.
- Неизменные state32/TX1336, очередь8×128, DMA1024/half512, RX/previous,
  TIME/ADC/USB, расписание grant и способы Stop/HELLO/Abort.
- ADC остаётся12-битным;150k передаёт10 старших бит с восстановлением
  кодового масштаба. Это не увеличение физической точности.

Production выбирает отдельный исходник оптимизированного serializer;
прежний прототип и SE остаются доступным эталоном. Build кандидата
`V2SF/0x56325346` отличает его при HELLO и в диагностике.

## Необходимые свидетельства

Один адресный differential проход против SE на полезных данных, границах
COBS/quantum и ошибочных состояниях; одна actual-core модель ownership,
Stop/HELLO/epoch/final-TIME; успешная ARM-сборка со сравнением изменённых
циклов и новым RAM/stack bound. Число инструкций — статический расчёт,
не замер циклов или WCET. Не переносить прежний stack bound без проверки.

При неизменном wire fixture уже проверенный host/Windows-пакет сохраняется;
повторная GUI-проверка не нужна для изменения только firmware serializer.
Независимый критик проверяет точные исходники и результаты. Программная
приёмка не закрывает требование устойчивого потока.

Следующий аппаратный шаг готовится отдельным точным планом: свежая копия
установленной SE, один Flash/readback, фактическое USB-переподключение,
150k/30с. Только после успеха — короткие50/100k проверки того же образа.
При отказе сохранить отрицательный результат, завершение владельца COM,
END/ACK и свежую диагностику; не повторять START автоматически. Аналоговая
полоса, входная точность и зажигание этим опытом не проверяются.
