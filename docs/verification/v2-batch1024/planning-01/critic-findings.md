## Найденная ошибка, исправленная до первого native

В первоначальном `collect` запись через OR в общий байт могла сохранить speculative high bits. Сценарий: опубликован один отсчёт; work-state добавляет `q=1023`, admission отклоняется; следующий work-state добавляет `q=0` в те же байты. Старый OR оставлял данные отвергнутого значения, хотя candidate canonical CRC считал ноль.

Автор заменил запись: сохраняются только уже принадлежащие опубликованному состоянию low bits `(1<<shift)-1`, остальные биты перезаписываются. Критик прочитал исправление. В третью существующую группу добавлен точный witness, сохранённый native PASS включает его. Отдельного расширения набора не потребовалось.

Другой важный край: COBS разрушает уже обработанный raw. Откат одной структуры state не откатывает storage. В header теперь прямо запрещён retry прежнего cursor после invalidation; нужен abort всего кадра. Native проверяет abort после 17 байт COBS и невозможность последующего piece/commit. Это условие будущего caller, не доказательство готовой обработки epoch.

## Обязательные границы будущей интеграции

1. **Владение данными.** После раннего pop имеются три разные области: подтверждённый prefix, принадлежащий staging диапазон, оставшаяся очередь. `queue.empty` больше не означает отсутствие неотправленных данных. END, quiesce tail, потеря блока и produced/unknown-tail должны учитывать staging. Нельзя объявить освобождённые слоты доставленными. При quantum до 512 отсчётов нужно проверить все queue views, включая переход кольца, до атомарного pop и публикации work-state; нельзя считать отдельные slots одним непрерывным массивом или добавлять скрытый большой scratch.
2. **Stop/HELLO.** До production нужна одна конкретная таблица для COLLECT, CRC, COBS, READY с offset=0, известного partial send и unknown acceptance. Stop запечатывает только фактически удержанные данные после quiesce; после последнего short не появляется новая DATA. При replacement HELLO частичный старый immutable кадр либо заканчивается под старой identity, либо обрывается существующим доказанным barrier/delimiter. Альтернатива должна быть выбрана и проверена actual core; логический `final_guards_valid` прототипа этого не доказывает.
3. **Commit.** Seed/first/global prefix, nonce/generation/config/sequence, epoch и итоговая TIME-проверка относятся к одному кадру. Предварительный canonical CRC допустим; его публикация вместе с end — только после всех известных принятых байтов и исходных final guards. Успех `accepted(0)` не подтверждает ни байта; отказ на SIZE_MAX требует вызывающего recovery.
4. **Память.** `19564 + 792 + 32 = 20388`, запас 92 байта при сохранённом резерве стека 8192 — корректный расчёт. Это не «стек 92 байта» и само по себе не доказательство невозможности. Но новые globals, alignment, tickets и полный call graph ещё не включены в linked proof. ARM object text1208/data0/bss0 и максимальные 36 байт отдельной функции не заменяют SRAM/stack полного образа. Большие RX/previous, message1300, raw1328 или второй canonical1024 scratch недопустимы в заявленном бюджете.
5. **Планировщик.** Quantum512 ограничивает отдельный вызов, а не гарантирует скорость. Наивные отдельные проходы для collection, CRC, COBS и четырёх USB fragments могут съесть экономию числа DATA. Пока единственный TX занят CRC/COBS/отправкой, следующий пакет хранится в прежней очереди. Deadline DMA-half остаётся около 3,413 мс; длительность DATA1024 около 6,827 мс не даёт большего времени обслуживания ADC. Canonical проект уже отмечает этот риск. Нужен точный ограниченный порядок работы, затем физическое свидетельство; увеличивать очередь для сокрытия причины не предлагается.

## Host draft

В прочитанном изменённом пути конкретного блокирующего дефекта не найдено:

- Большой envelope допускается только DATA0.3/config5; CRC/framing/header проверяются до фильтра nonce. Старые control/режимы остаются ограничены 512/544.
- Host продолжает читать максимум 544 байта за один receive; аккумулятор собирает один кадр до 1335. До полного delimiter и проверок count/padding/session/index новые samples не публикуются. Тестовый cut-frame сохраняет прежний prefix.
- Discovery/selected ACK имеют строгие пары max_block/max_payload; public150 требует marker15/mode5, SC/SD отклоняются до START без fallback. Mode3/4 не переопределены.
- Intrinsic marker согласован с config5, source12/retained10; canonical коды кратны четырём. Старые версии файла и companion не переписываются. Journal cap 8192 и raw byte cap не требуют увеличения из-за DATA1024.

Пока это ограниченный source audit и сохранённые unit evidence. Actual C→host fixture ещё ожидается. GUI, новый Windows-пакет и совместная runtime работа не проверены; прежний GUI helper ещё ориентирован на mode4 и это явно указано в draft manifest.
