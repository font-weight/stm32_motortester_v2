# V2-06i: предложение host-контракта 50k/12 и 150k/10

24.10.2026. Read-only аудит после H2. Это предложение для согласования
root/firmware, production не изменён, аппаратных действий и повторения H2 нет.
Нормативные имена file enum и окончательные версии — `host/docs/stream-modes.md`.
Пользователь подтвердил выбор50/100/150 в UI до захвата. Проверенный
100k/12 сохраняется отдельным режимом/образом возврата; условный packet-fallback
для неудачного100k больше не требуется, поскольку H2 прошёл30с.

## Рекомендуемое представление

**Упаковать старшие10 бит в прошивке; на ПК хранить их в исходном 12-битном
масштабе, с явным признаком утраты двух младших бит.** STM32 остаётся физически
настроенным на12-битное преобразование. «10 бит» означает число сохраняемых
бит, а не новый аппаратный режим, ENOB, точность напряжения или ускорение ADC.

Пусть исходный код ADC `c` принадлежит0…4095. Передача: `q=c>>2` (0…1023).
Нормализованный сохранённый код: `c_norm=q<<2` (0…4092 с шагом4).
Преобразование `q↔c_norm` взаимно однозначно: сохраняется вся полученная от
устройства информация, но первоначальные два бита восстановить нельзя.
Нельзя называть такой массив «полными исходными12-битными отсчётами».
Автоматическая добавка1,5 или масштабирование1023→4095 не предлагаются.

| Вариант | Шкала и пороги | Последствия |
|---|---|---|
| `c_norm=q<<2`, рекомендован | `U_CH1=a*c_norm+b`; прежний code-domain0…4095, коды кратны4 | Минимальные изменения viewer/disk; обязательны retained_bits/quantization и новые правила края диапазона |
| `q` как uint16 raw0…1023 | `U_CH1=(4a)*q+b`; пороги/rails пересчитываются в10-битный domain | Нужен явный новый домен коэффициентов, порогов и экспортов; ошибочное применение прежнего a уменьшит показание в4раза |

Второй вариант не требует физического повторного измерения только ради
алгебры `a10=4*a12`, но требует производного профиля с происхождением и
другим code-domain. Он не становится новой измеренной калибровкой. Первый
вариант сохраняет форму имеющейся калибровки, но тоже не сохраняет её
разрешение: для данного c_norm неизвестный исходный код лежит в
`[c_norm,c_norm+3]`; ошибка усечения в напряжении не превосходит `3*abs(a)`.
При отрицательном a границы напряжения упорядочиваются отдельно.

Текущий `StreamContext` вообще допускает только `UNKNOWN_PROFILE`
(`host/motortester/v2/stream_device.py:121–135`), поэтому этот этап сам по себе
не включает физические В/мВ в поток и не создаёт коэффициенты из CAPS.

## Упаковка и контроль целостности

Предлагаемая каноническая спецификация: последовательный little-endian
битовый поток q10. Четыре кода образуют
`w=q0 | (q1<<10) | (q2<<20) | (q3<<30)` и5 младших байтов w.
Длина массива равна `ceil(10*N/8)`; последний неполный блок разрешён,
неиспользованные старшие биты последнего байта строго нулевые. DATA count
по-прежнему означает отсчёты, а не байты. Обязательны точная длина, предел
1…128, корректный config/generation и отсутствие ненулевых pad-бит.

CRC кадра считается по фактическим упакованным wire-байтам. END prefix CRC
для нового контракта следует считать по нормализованным `uint16-le c_norm`
в обоих концах. Нельзя оставить CRC от первоначальных c: после удаления
бит ПК его не сможет проверить. Для12-битного режима этот CRC-домен остаётся
прежним. В новой версии контракт прямо называет домен CRC; недекодированные
wire-байты при физической проверке остаются отдельным свидетельством.

При прежних24 байтах заголовка,20 байтах DATA metadata и4 CRC:

- DATA128/10:160 байт массива,208 decoded, максимум210 framed с COBS/нулём.
- DATA128/12 в uint16:256 байт массива,304 decoded, максимум307 framed.
-150000/128×210≈246094 wire-байт/с против100000/128×307≈239844: всего
  около+2,61% номинальной нагрузки. Это не измеренная пропускная способность.
- В journal c_norm остаётся uint16:300000 raw-байт/с. Packing уменьшает USB,
  но не удваивает лимит записи на диске.256KiB raw-очередь ≈0,874с при150k,
  а1024 DATA128-элемента — тот же131072samples; время буфера не увеличивается.
- DMA512 half при150k даёт3,413мс вместо5,12мс. Усечение бит не сокращает
  физическое ADC-преобразование; новую частоту/ADC timing проверяет firmware.

Не увеличивать DATA count, очередь, FIFO или burst вместе с новым форматом
без отдельной причины: выгоду packing и стоимость обработки иначе не разделить.

## Согласование режима до START

Рекомендация — явный **wire0.3** для новой согласуемой многорежимной сессии,
с сохранением точного decoder0.2 для прежних устройств/записей. Нельзя
переиспользовать reserved-поля0.2 или молча назвать packed payload прежним DATA:
текущий decoder требует config/profile1,12бит, `20+2*N` и revision0.2.

Предлагаемый минимальный поток, окончательные enum/байты фиксирует общий
контракт с firmware:

1. UI выбирает `50k/12`, `100k/12` или `150k/10` **перед Connect**.
   Модель UI не связана с профилями «Осциллограф»/«Зажигание».
2. HELLO0.3 несёт новый nonce и requested acquisition mode
   (payload `<QHH`: nonce, mode_id, reserved0;
   mode1=50k/12,2=100k/12,3=150k/10). Ответ сообщает
   поддержанные режимы/выбранный mode; неизвестный режим отклоняется.
3. GET_CAPS без payload возвращает неизменяемый контракт выбранной сессии:
   config_id/mode_id/CH1/physical ADC bits12/retained bits/encoding/
   quantization/fs numerator/denominator/maxblock/CRC-domain. Host требует
   точного соответствия выбранному режиму; ошибка не вызывает тихий fallback.
4. START payload `<I>` содержит точный config_id=mode_id в namespace0.3,
   связывается с этим config/mode и сохраняет нынешние nonce,
   generation, sequence, reserve/deadline и first_index0. После START режим
   заблокирован до закрытия сессии. Изменение требует новой явно видимой
   остановки/сессии/nonce, а не команды перенастройки действующего ADC.

Это использует границу HELLO/CAPS/START, а не новый active-session CONFIG.
С firmware-автором согласован discovery без timeout-downgrade: новый host
сначала отправляет всем обычный HELLO0.2/8B. Старый ACK с capability1 ведёт
в неизменённый fixed-Fs0.2 путь; новый firmware отвечает HELLO_ACK0.2 с
capability3 как явным признаком перехода на0.3. Старый app уже отвергает такой
ACK до START. Новый host завершает discovery и отправляет HELLO0.3 с новым
nonce, выбранным mode и снова seq/request1. Discovery не запускает ADC и
не разрешает старый0.2START; допускается только новый HELLO. Смена nonce в
firmware подтверждается после accepted ACK/isolation по прежним правилам.
Ни тайм-аут, ни ошибка формата не вызывают скрытого повторного START или
понижения выбранной Fs. Для legacy-платы показывается только фактическая
фиксированная Fs и ограничение выбора.

Согласованная компактная CAPS0.3:24B `<IHBBIIHBBI>` — config_id, mode_id,
channel0, adc_bits12, Fs_num, Fs_den1, max_block128, retained_bits, encoding,
flags1. Encoding1 — u16le12 для mode1/2; encoding2 — packed10 для mode3;
число удалённых бит однозначно12−retained. Decoder требует точной таблицы
режимов/значений, не принимает произвольные комбинации. Поля discarded и
normalization в файле выводятся из проверенного контракта, а не угадываются
по амплитуде данных. Вариант SET_PROFILE/CONFIG_ACK + отдельный DATA10 kind
на wire0.2 сохранял бы номер версии, но добавлял бы изменяемую конфигурацию
и отдельные переходы состояния. HELLO0.3 даёт immutable session mode и
изолирует новую семантику DATA/CRC от существующего0.2.

## Файл, происхождение и открытие старых записей

Новая информация должна входить **в проверяемую identity самого journal**,
а не жить только в `.v2.json`: `source_adc_bits=12`, `retained_bits=10|12`,
`wire_sample_encoding=u10packed_le|u16le`,
`normalization=left_shift_2|identity`, `quantization=truncate_lsb|none`,
`stored_sample_encoding=u16le`, `stored_code_domain=adc12`, mode/config и Fs.
Это характеристики принятого контракта; `image_verified` остаётся false,
unknown accounting/produced tail не меняются.

Текущий reader `_construct` требует точного набора dataclass-полей
(`stream_recording.py:84–93`). Простое добавление default-fields сломает старые
файлы. Нужна явная ветка формата: новый writer с новым magic/version для новой
identity; старые magic1/2 читаются прежней схемой, затем **в памяти** получают
эквивалент `retained_bits12/quantizationnone`. Старые bytes/hash не переписываются.
Прежние50/100/200k записи остаются читаемыми;200k не исчезает из reader лишь
из-за отсутствия этого пункта в новом UI. Новый файл без нужной metadata
не должен открываться как неизвестный «обычный12-bit».

Companion получает явную новую format_version и связывает ту же expanded
identity/CAPS с SHA journal. Session/view selection keys, store-job identity,
reopen/export и provenance validators должны включать mode/quantization,
иначе одинаковые nonce/Fs не защищают от смешивания представлений.
CSV оставляет индекс и время `index/Fs`; столбец кода подписывается
«код в масштабе12бит, сохранены10». JSON экспортирует все поля квантования.
Первоначальные discarded bits не экспортируются как нули, якобы измеренные ADC.

## Отображение, края диапазона и минимальные проверки

150k требует номинального шага `1/150000`с≈6,666667мкс; нельзя округлить его
до6 или7мкс и накапливать по тактам. Существующее время от индекса/Fs подходит.
Навигационные окна, заданные в отсчётах50k, масштабируются×3; пороги в c_norm
остаются в12-bit domain. Размер recent ring65536 означает≈0,437с при150k.

Старый критерий `code==4095` не поймает верхний q10-код c_norm4092.
Нужны rails-aware предупреждения:0 и4092 обозначают **крайнюю корзину
квантования**, но не доказывают, что исходный ADC был точно0/4095. EventConfig
rails и пользовательская подпись должны согласовываться; потерянные два бита
не позволяют реконструировать прежний точный признак ADC saturation.
Диапазон аналогового входа этим переключателем не расширяется.

После согласования достаточно адресных проверок: несколько независимых
packing-векторов (включая неполные блоки/ненулевой padding); bind выбранного
CAPS→START и отказ смены на живом потоке; roundtrip одного packed10 журнала
с полной raw/CRC equality и экспортом времени; чтение старой12-bit записи;
один короткий synthetic GUI50↔150 выбор до START. Реальный150k опыт — отдельно
после exact firmware/Windows-кандидата и review. Программные проверки не
подтверждают физическую10-bit точность или устойчивость150k.

Затрагиваемые host области после согласования: stream_wire/endpoint/bridge,
stream_model/recording/provenance/view, V2 stream_device/GUI/context и экспорт.
Главный DEMO/оконный wire0.1 и физическая InputProfile-калибровка не должны
получать бессмысленную глобальную замену12→10.
