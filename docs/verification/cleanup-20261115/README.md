# Состав очистки от 15.11.2026

Это разовая очистка локальных сборок, а не новая версия приложения.
Фактический результат и выполненные проверки — в [progress.md](../../progress.md).
Границы работы — [SCOPE_RU.md](SCOPE_RU.md), точные кандидаты — [plan.json](plan.json).

В список включены старые окружения Python, копии установочных пакетов,
промежуточные файлы PyInstaller, распакованные дубли ZIP и точные кеши.
Исходники и история Git, пользовательские записи, схемы, резервные копии
прошивки, инструменты и уникальные материалы прежних проверок сохраняются.
Пути запуска текущего `build/v24w` и предыдущего `build/v23w` не меняются.
Окружение сборщика `build/v18w2`, основной `.venv` и worktree `build/v18src`
не входят в список удаления.

## Если понадобится старая сборка

У удаляемой распакованной копии сохранён соответствующий ZIP:
его путь и SHA256 указаны в `evidence.archive` соответствующей строки плана.
Распакуйте этот архив в прежний каталог `dist` либо `Проверка переноса`.
Не запускайте старые исторические команды, предполагая, что временное
окружение сохранилось: создайте новое по lock-файлу той версии.
Копии wheels, совпавшие побайтно, остаются в `build/v18w2/wheelhouse`.
Текущая установка из чистого клона описана в корневом README.

Журналы предупреждений и карты импортов из PyInstaller сохранены отдельно
в `build/<имя сборки>/pyinstaller-diagnostics/`;
[соответствие путей и контрольные суммы](retained-diagnostics.json).
Старые отчёты сборок не переписываются: их прежние пути описывают состояние
на момент проверки, а не обещают наличие всех временных файлов сегодня.

`verify_plan.py` выполняет только чтение и проверку. `remove-approved.ps1`
удаляет только точные разрешённые каталоги после проверки состава, хешей,
отсутствия защищённых файлов, ссылок и запущенных из этих каталогов программ.
Это свидетельства разовой операции; повторный запуск после удаления
должен остановиться на отсутствующих целях, а не искать новые автоматически.

`verify_after.py` сверяет локальный снимок сохранности сразу после удаления.
Этот контроль выполнен до добавления итоговых записей в decisions/progress;
последующие изменения документации оцениваются отдельно по Git diff.
Скрипт не предназначен для повторного запуска после дальнейшей разработки.
