## Результат проверки кода

Прежний `inspection_reset` сопровождал выбор события и ставил главному окну
флаг начальной развёртки. Следующая отрисовка возвращала прежний диапазон.
Теперь отдельный `source_reset` используется только при замене источника;
явный выбор события имеет приоритет также до первой отрисовки.

Live-событие удерживает immutable raw текущего snapshot, ограниченный прежним
лимитом 65 536 отсчётов uint16. `select_range` запрашивает данные через
существующий bounded reader/worker; новые snapshot обновляют метаданные,
но не подменяют удержанный график. Запись не приостанавливается. Курсоры
по-прежнему сбрасываются при выборе события, а «К хвосту» снимает удержание.
Исходный журнал, частота, амплитуда и калибровка не преобразуются этой правкой.

ДЕМО, тестовый пропуск, старая оконная прошивка и сведения о шкале перенесены
в «Сервис». Действия меню повторяют доступность прежних контролов. Основной
вход в поток остаётся над крутилками; неприменимые верхние вкладки и второе
подключение скрыты только на странице потока. ДЕМО остаётся доступным для
проверки без платы и явно помеченным, включая стартовый экран; полное удаление
ДЕМО не заявляется. У неизвестного входа не появляются выдуманные В/мВ.

## Ограничения и оценка

Новая итерация не подтверждает реальную запись 150k, точность Fs/напряжения,
зажигание, автомобиль или чистую Windows без Python. Live-память ограничена:
выбранное доступное событие удерживается, но переход к давно вытесненному raw
требует открытия записи. Событие — результат порогового поиска, не диагноз,
цилиндр или измеренное время горения. Зум/крутилки проверяются сценарием через
сеттеры контролов, нажатия кнопок — через Qt click/trigger; полноценная ручная
проверка всех жестов не заявлена. Pause/export отдельным новым сценарием этой
итерации не проверялись; их код не менялся. Дополнительные тесты для количества
не требуются. Следующий шаг — пользовательская проверка обеих кнопок в новом EXE.
