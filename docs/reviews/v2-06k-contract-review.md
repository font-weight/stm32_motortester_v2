## Корректность и совместимость

Новый **wire0.3/mode4/config4** явно означает150k/10 сохранённых бит/DATA256.
Mode3 остаётся150k/10/128, modes1/2 —50/100k/12/128. Discovery допускает ровно
пары capability/max1/128,3/128,7/256. Global discovery maximum отделён от
selected ACK/CAPS maximum; выбранные mode/config/Fs/разрядность/encoding/max
обязаны совпасть до START. Новый host на SC150 явно отказывает до START,
без скрытого возврата к mode3; SC50/100 и legacy fixed-Fs проверки сохраняются.
Лично прочитан существующий `decode_payload(HELLO_ACK)` SC: он требует
block128 и capabilities1/3 для discovery, поэтому прежний I-host отвергнет
новое7/256 до START. Проверка чтением, не запуск старого приложения.

Не требуется wire0.4 только ради новой строки закрытой таблицы. Старый mode3
не переопределяется. Pending/current/TX identity, checked envelope, fresh nonce,
partial HELLO isolation и fail-closed правила наследуются из I. Номер build
не заменяет согласование и точный SHA образа. Отдельный CAPS flags1 и END
не получают нового значения.

В новом режиме объединяются два уже существующих queue128. До любого
изменения CRC/prefix/queue проверяются оба view и смежность индексов;
нельзя pop первого и лишь затем обнаружить stale второго. Ticket фиксирует
обе части и решение объединить. Полный accepted DATA продвигает prefix на
фактическое число отсчётов, а sequence — один раз. Known0, partial/unknown,
TIME/epoch и post-write failure сохраняют прежнюю границу принятого префикса.

STREAMING выдаёт полные256 без блокировки foreground при ожидании пары.
Short1…255 разрешён только после синхронного Stop/fault quiesce, tail append
и seal, когда исчерпывает сохранённую очередь. Lone128 уходит при Stop;
остаток257 означает256+1. После short DATA новых DATA нет. Отсутствующие
отсчёты не заменяются нулями, неизвестный произведённый хвост сохраняется.

Intrinsic marker `0.3-batch256-20261024` вместе с mode4 однозначно задаёт
wire maximum256 в неизменяемом registry. Структура17 полей и magic3/4,
companion3 не меняется; неизвестный enum у старого reader приводит к отказу,
а не к неверной интерпретации raw. Открытие без companion сохраняет mode4
и потерю2LSB. Journal chunk8192 не ограничивается wire maximum256 и старые
агрегированные записи остаются допустимыми. Canonical коды0…4092, кратные4,
CRC по u16le, `U_CH1=a*code+b` и время index/Fs прежние. Требовать новое поле
max в journal при такой закрытой таблице оснований нет.

## Лично проверенные расчёты и ограничения

HELLO0.3 имеет12байт, ACK16, CAPS24, DATA metadata20. Для256×10бит packed
часть320байт, payload340, decoded envelope368. Безопасная граница COBS с
delimiter — `368+floor(368/254)+2=371`, запас до FIFO384 составляет13байт.
Прежние payload512/frame544/staging544 достаточны по размеру. Один DATA
разворачивается в512 canonical байт; raw byte cap и queue не увеличиваются.

При150k полных кадров585,9375/с вместо1171,875/с; worst DATA wire нагрузка
217382,8125B/s вместо246093,75B/s. Условные6 USB-пакетов относятся к отдельно
переданному371-байтному кадру, не к измеренной структуре CDC/ISR. Сохраняются
150k=`72MHz/(48×10)`, период20/3мкс, прежние ADC/TIM3/DMA/TIME и CEN/deadline.
Номинальный расчёт не подтверждает устойчивость, аналоговую полосу или ENOB.

Увеличение guarded canonical CRC и старение early-grant до публикации могут
ограничить фактическую скорость. Второй grant, рост очереди/FIFO или J TIME
optimization не входят. Первая задержка не объявлена обязательно большей:
DMA half512 может уже опубликовать оба128-блока. Сохранившиеся932байта SRAM
SC сверх8192резерва не гарантируют размер нового ticket/view; нужен exact
ARM/static результат реализации.

Расчёт и проверка документов выполнены PowerShell и `.venv/Scripts/python.exe
-B -` (Python3.14.7, Windows10.0.19045): hashlib/byte comparison, существование
ссылок, `struct.calcsize` и `fractions.Fraction`. Первый расчётный вызов
исправлен после опечатки формата struct; production и implementation tests
не запускались. Результаты проверок включены в JSON этого ревью.

## Дальнейшие обязательные свидетельства

Открытых P0/P1 **в контракте** нет. Закрыты неоднозначности wire256 против
journal8192, mode3 против mode4, global против selected max, atomic pair и
terminal short, а также необоснованное обещание большей первой задержки.

Достаточны одна адресная actual-core/queue/wire модель пары, wrap7→0,
stale второго view до CRC/pop, известное нулевое/частичное/неизвестное
принятие, pending DATA при HELLO/Stop, хвосты из контракта и257→256+1;
адресная сверка неизменных guards, exact ARM/SRAM/stack. На host — строгая
совместимость negotiation, независимые packing/padding и mode/count границы,
actual C→Python DATA256+tail+END, fresh Open без companion и прежний mode3.
Затем один адресный Windows GUI/frozen package flow. Это план, не выполненные
свидетельства; весь унаследованный набор повторять не требуется.

Аппаратный план/допуск — отдельно после exact software/package. Legacy136
остаётся one-attempt-per-boot: новый boot и подтверждённое USB-переподключение
для каждого диагностируемого сеанса, собственный nonce/generation в дампах.
Нет аппаратных действий критика. Не принимаются150k, напряжение/полоса,
калибровка или автомобильная безопасность.
