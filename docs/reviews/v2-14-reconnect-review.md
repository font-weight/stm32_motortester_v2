## Контракт и код

Переподключение допустимо после завершения старого приёма и сохранения
контекста. Оно сохраняет страницу, viewer, курсоры и файловый worker,
но создаёт новый bridge только после finished прежнего, то есть после join
его владельцев и подтверждённого закрытия OS handle. Общая резервация COM
остаётся за страницей. Отказ close не создаёт второго владельца; доступен
только повтор cleanup. При окончательном закрытии страницы новый bridge
не создаётся, а общий lease освобождается обычным путём.

Все пять старых callbacks — state/live/error/saved/finished — проверяют
identity bridge. Повторяемая revision нового контроллера не используется
как единственная защита от старого ответа. Незавершённая файловая операция,
пикер записи и metadata failure блокируют новое подключение. Активная запись
и параметры поиска остаются отдельными состояниями: сначала Stop, затем
настройка/переподключение, затем отдельный «Живой поток».

После Stop применённый draft поиска не меняет config завершённого сеанса
или companion. Файловое переиндексирование имеет свой config. При новом
READY последние live-настройки возвращаются только при совпадении
согласованных Fs/retained bits; иной режим получает явный сброс. Временная
ошибка HELLO не уничтожает ожидающий draft. До успешного READY открытый
архив остаётся доступным; после READY сбрасывается только его отображение,
не исходный файл. Готовая raw-копия отдельного захвата остаётся доступной
для Save. Несохранённый кадр требует решения пользователя.

При уже открытом подтверждении reconnect последующий close заменяет
ожидаемое действие: Discard закрывает, Cancel снимает намерение закрыть
главное окно. Более поздний обычный reconnect не вытесняет close. Новый
Connect проверяет возможности без START, счётчик READY остаётся нулевым.
Смена самого COM-порта и горячее изменение поиска не входят в этот этап.

## Замечания и исправления

1. **P2, закрыт:** при закрытии главного окна поверх уже открытого
   dirty-reconnect prompt прежний callback мог оставить pending-close
   или начать reconnect вместо закрытия. В `confirm_discard` добавлена
   замена пары callbacks по приоритету close. Final frozen проверяет
   `window.close → Cancel`, прежний bridge/dirty-кадр и сброшенный pending-close.
   Ветка Discard и невозможность обычным reconnect вытеснить close проверены
   чтением кода; они не объявляются отдельным динамическим опытом.
2. **P2, закрыт:** после неудачного HELLO отсутствие connection стирало
   последний live draft на следующей попытке. Теперь config+basis сохраняются
   до успешного согласования. Final frozen включает write failure HELLO,
   доступный файловый поиск2800, retry и восстановленный live2500 без START.
3. **Ошибка свидетельства, закрыта:** второй frozen ожидал `state.error`,
   хотя инъекция записывает `serial.first_error=TransportWriteError` и
   endpoint `write_count_unknown`. Диагностический снимок подтвердил
   доступные can_open/Connect при0 отсчётов. Исправлен только предикат
   сценария с явной проверкой endpoint-кода; неудачный результат сохранён.
4. **P3 V2-13, закрыт:** временная подпись сохранения больше не утверждает,
   что приём продолжается после Stop. Используется нейтральное
   «Сохраняется отдельный захват…».

Открытых обязательных исправлений в пределах V2-14 не обнаружено.
