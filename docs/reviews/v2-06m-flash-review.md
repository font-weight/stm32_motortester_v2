## Прочитанная дельта и условия допуска

Шесть перенесённых helpers сравнены с L: изменены пути/build/report labels,
проверки wire/raw/диагностики/остановки сохранены. Новый `run_trial.py`
проверяет точный admission hash, pins, подтверждённый readback, выбранную Fs,
запись нового ответа пользователя с hash соответствующего reset.log и
PASS-гейты всех предыдущих сеансов. Создание нового каталога запрещает
автоматический повтор того же START. Это привязка сохранённых свидетельств;
реальность сброса и ответа пользователя остаётся обязанностью оператора.

1. Перед действием root подтверждает отсутствие владельцев COM/приложения,
   COM6 и единственный ожидаемый ST-Link. В сохранённом backup.log есть SN
   `57005400120000393333574E`; generic SN в List не используется как identity.
   PA0 пуст, питание только USB платы/без ST-Link3.3V — условия пользователя,
   не независимое наблюдение критика.
2. Один program/verify; отдельный Dump всех42480 байт должен совпасть с BIN
   до Reset. Проверяются exit0, ожидаемый SN и реальные success strings.
   Затем успешный Reset/Run и **новое фактическое** USB-переподключение с
   ответом пользователя. Прежнее «всё подключено» этот ответ не заменяет.
3. Первый сеанс —150k/mode5 на30 секунд Record. Только после полного PASS —
   50k/mode1 и100k/mode2 по5 секунд. Перед каждым новый Reset/Run/replug для
   одноразовой диагностики; один START. Build/discovery15/new selected nonce/
   CAPS проверяются до START. Требуются длительность, normal END/STOP_ACK,
   индексы/CRC/все сохранённые коды/fresh Open и явный неизвестный хвост.
4. SWD/halt запрещены при активном owner. Сначала закрытие и normal END/ACK;
   для reason1 допускается только отдельный fault-reader после cleanupclosed
   и matching terminal ACK. Затем две136 и точные TIM3/ADC/DMA/RCC блоки,
   без ADC_DR. PASS требует текущих build/nonce/gen, flags0, poll/copy ниже
   3413/10240/5120 мкс для соответствующей Fs и остановленных регистров.
5. Любой отказ прекращает план. Не повторять START автоматически; throughput
   failure сам по себе не основание отката. Возврат SE — только при конкретной
   необходимости восстановления запуска/связи/остановки. Реальную хронологию
   root сохраняет отдельно: автоматически созданные helper facts её не заменяют.
