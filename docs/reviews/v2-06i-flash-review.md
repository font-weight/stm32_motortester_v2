## Обязательные условия исполнения

1. Только root работает с аппаратурой, на той же плате/проводке с пустым PA0 и закрытым приложением. Один program exact38188 по0x08000000 с verify, затем отдельный полный readback и побайтное совпадение **до** reset/run. После него требуется фактическое пользовательское USB-переподключение и ответ; ожидание по времени его не заменяет.
2. Максимум три отдельные попытки, в порядке **50k/12 — Record5с;100k/12 — Record5с;150k/10 — Record30с**, по одному START каждая. Это время Record после Preview; сохранить фактический wall/overshoot. Перед каждым START — новый Connect/discovery0.2, свежая выбранная nonce0.3, exact SC build и совпадающие mode/config/Fs/ADC12/retained/encoding CAPS. Нет смены режима работающего захвата, скрытого fallback или второго START.
3. Между успешными сеансами закрыть COM, сохранить и проверить весь предыдущий результат до следующего Connect/START. **Любой отказ прекращает оставшуюся последовательность.** Без повторного опыта с меньшей частотой или автоматического USB-reset. Успешная ветвь подтверждает `owners_closed=true`; ошибочная — `cleanup_finished=true` и `final_state.phase=closed`. До подтверждения закрытия SWD запрещён; во время приёма запрещены SWD и halt.
4. После каждого закрытого сеанса — два одинаковых frozen136 по0x20002BD4 с actual nonce/generation/build, flags0 и poll/copy строго ниже10240/5120/3413 мкс соответственно. Сохранить отдельные TIM3/ADC/DMA/RCC: CEN0, PSC/ARR71/19,71/9,47/9; ADC_CR2=0,SMPR2 low3bits4; DMA EN0; нужные clocks включены, reset снят. Заполнители nonce/generation из плана заменяются только фактическими wire значениями. При отказе диагностика сохраняется только после подтверждения закрытия и неактивного состояния.
5. Физический результат требует нормального END reason0 после STOP и matching ACK, непрерывных sequence/index/CRC, fresh Open/companion и побайтного совпадения выбранных raw с wire. Для150k — код0…4092, кратность4, retained10/drop2 и nominal20/3 мкс. Исходные два LSB не заявляются сохранёнными. Неизвестный произведённый хвост остаётся неизвестным.
6. Грубый темп по ПК —45–55k,90–110k,135–165k в соответствующих сеансах, не калибровка таймера. Per-session audit cap16MiB; номинальные DATA≈0,60/1,20/7,38MB не гарантируют вместимость при произвольной фрагментации с13 байтами на chunk. Audit overflow — отказ логирования, не доказанный devicequeuefull. Общий wall/no-halt сохраняются отдельно; не выводить elapsed из DWT через неизвестное число оборотов≈59,65с. `tx_max` исключает prepare/encode.
7. **Не откатывать автоматически после отказа потока.** При подтверждённых загрузке/связи/остановке оставить SC. Только при конкретной необходимости из плана — неверифицированный program/readback, отсутствие boot/связи после запланированного replug либо неподтверждённая остановка — записать основание, восстановить свежую полную SB65536 с verify/независимым полным readback, reset/run и пользовательским replug. Затем SB-only READY без START. S4 не является обычной целью восстановления.
