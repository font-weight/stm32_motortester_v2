## Результат проверки контракта и кода

Arm берёт `processed_until` свежего опубликованного снимка контроллера,
а не отрисованного кадра. Документирован предел этого решения: это граница
обработки на ПК, не аппаратная отметка щелчка. Уже активное до arm событие
исключается по ordinal и trigger; выбирается первый следующий кандидат,
не последний доступный. Утрата первого кандидата или его raw завершает
попытку явно, без тихого перехода к следующему событию.

Подтверждается пересечение двумя соседними исходными кодами. Контекст задаёт
сохранённый EventConfig; масштаб просмотра его не меняет. Готовый захват
владеет immutable raw-копией и снимками identity/context/config/event,
переживает новые live-кадры, изменение вида и Stop. Приём и запись не
останавливаются от arm, отмены ожидания или удержания результата.

При Stop/ошибке до закрытия контекста сохраняется лишь уже наблюдавшийся
pending-префикс с `interrupted`/`right_truncated` и причиной. Контракт прямо
предупреждает, что более поздние данные могли уже поступить в контроллер,
но ещё не попасть в этот префикс. Неизвестные потери/хвост не превращаются
в нулевые потери или полный разряд. Ограничение raw — 65536 отсчётов,
дополнительно ≤200 мс EventConfig; бесконечного накопления нет.

`.mtshot` version1 содержит JSON, исходные u16le и SHA256, исходные индексы,
Fs/разрядность/происхождение, параметры поиска, флаги и причину завершения.
При 150k/retained10 сохраняются коды ADC12 с шагом 4, без восстановления
младших бит. Чтение ограничено размером и проверяет схему, конфигурацию,
границы, разрядность и само пересечение. Отдельный файл не получает
фиктивный STOP непрерывного потока. Старые `.mtstream`/companion не меняются.
Сохранение использует атомарную публикацию без замены существующего файла;
ошибка оставляет кадр доступным для повторения.

Готовый несохранённый захват защищён при следующем захвате, открытии файла
и закрытии. Отмена закрытия снимает намерение закрыть главное окно.
Открытый `.mtshot` показывает сохранённый поиск без переиндексации; курсоры
читают оригинальные точки. Отмена ожидания/ручная навигация/синхронизация
и смена источника имеют отдельные предсказуемые переходы.

## Замечания

Закрыты до приёмки:

1. **P2:** Cancel в новом диалоге несохранённого захвата не сбрасывал
   `_stream_close_pending`. Добавлен callback `close_cancelled`; адресный
   сценарий проверяет отсутствие отложенного закрытия после Cancel.
2. **P2:** arm до готовности первого viewer-кадра мог оставить принятый
   захват без отрисовки. Теперь проверяются selection/границы/identity и
   совпадение revision; неподготовленный viewer не начинает попытку.
3. **P2:** общий EventConfig сам по себе не связывал метаданные файла с Fs
   и retained bits. StreamCapture вызывает `validate_config`; final frozen
   включает отрицательный файл с правильной SHA и неверным rail4095 для
   retained10, наряду с допустимым rail4092.
4. **Компоновка:** автор уменьшил высоту графика и внутренние отступы после
   native PNG. Критик осмотрел финальные capture/open PNG: ось X видна.
   Подпись неполного контекста сохраняется и после успешного Save.

Открыт **P3, косметика:** `SingleCaptureControls.save_path` временно пишет
«Сохраняется отдельный захват · приём продолжается» также после Stop или
при сохранении открытого файла. Строка основного состояния отражает Stop;
данная ветвь не запускает АЦП/приём. В следующем обычном UI-изменении убрать
вторую часть либо выбирать её по фазе. Новая сборка только ради этой краткой
подписи не требуется для текущей приёмки.
