## Представленные проверки и их пределы

[Backend-журнал](../verification/v2-stream/backend-tests.txt) различает первоначальные четыре сценария, адресную проверку occupied-path и последующие shutdown-context, pacing, source-admission. Исполнители и условия указаны в нём: часть backend выполнял `v2_core`, shutdown-context и native GUI — основной агент. Начальный sandbox-отказ сохранён. Квитанция ранних backend-прогонов восстановлена из ранее полученного вывода инструментов; она не выдаётся за новый прогон чистого конечного commit.

По [native source receipt](../verification/v2-stream/source-smoke3/result.json): Windows 10 build 19045, Qt windows, R=12672, экспорт 19126 кодов, оба профиля, независимая пауза, закрытие дочернего/родительского окна, unknown tail и последующее открытие здорового файла. `serial_open_calls=0`, callback errors отсутствуют.

По [конечной квитанции пакета](../verification/v2-stream/package/build-report.json) и [журналу](../verification/v2-stream/package/build.log): пакет распакован в путь с кириллицей, запущен из другой рабочей папки при PATH только `System32`, Windows 10 build 19045, Python 3.14.7, Qt 6.12.0. Frozen smoke завершился с кодом 0 за 5,447 с; обычный GUI entrypoint — с кодом 0 за 2,245 с. Сохранены также успешные CLI-проверки обычного файла и synthetic оконного файла. Это наблюдения одного компьютера; они не доказывают работу на чистой системе или длительную потоковую производительность.

Frozen smoke проверяет настоящий экспорт/повторное открытие файла, обе synthetic-формы, паузу при росте raw, фактическое ненулевое R после Preview, Escape и завершение writer при закрытии главного окна. Старые оконные функции остаются в упаковочной проверке. Повторять весь унаследованный набор для этого изменения оснований не было.

## Замечания и закрытие причин

| ID | Приоритет | Первоначальная причина | Конечное состояние |
|---|---|---|---|
| S-R1 | P1 | Экспорт резервировал JSON, затем пытался повторно создать его через exclusive atomic write; успешный CSV не завершал экспорт | Закрыто: JSON завершается через собственный уже зарезервированный дескриптор. Подтверждено конечным CSV/JSON и raw roundtrip |
| S-R2 | P1 | Ошибка сохранения контекста могла исчезнуть при shutdown, после чего окно закрывалось; аналогично могла скрыться ошибка файловой операции | Закрыто: удерживается точная `ContextFailure`, Retry/Abandon/Cancel относятся только к ней; writer/raw не удаляются. Ошибка файловой операции отменяет ожидающее закрытие родителя. Адресный backend и чтение GUI-переходов согласованы |
| S-R3 | P2 | После открытия файла оставались счётчик и failure предыдущего live-сеанса | Закрыто: число отсчётов берётся из открытой записи, live failure не переносится. Конечный smoke открывает здоровый файл после unknown-tail |
| S-R4 | P2 | Новый источник мог сохранить старый график; одной очистки GUI было недостаточно из-за queued/late display старой revision | Закрыто: очистка на новом Preview/direct Record и admission fence минимальной revision в bridge. Fence сохраняется при немедленном Stop; Preview→Record своего поколения не сбрасывается. Адресный тест и чтение конечного кода |
| S-R5 | P2 | Проверка существования выбранного пути выполняла filesystem I/O в GUI | Закрыто: preflight удалён, исключительное создание выполняет владелец записи |
| S-R6 | P2 | Pause→Stop продолжал сообщать, что приём и запись идут | Закрыто: нейтральное «Просмотр на паузе», состояние приёма сообщается отдельно |

Авторские проверки дополнительно выявили две причины native FAIL: слишком малый synthetic scheduling budget и непереданный первый viewport. В конечном коде период заранее рассчитан, catch-up явно ограничен 32768 отсчётами/655,36 мс, превышение остаётся overrun; viewport публикуется с дедупликацией. Это не изменение допустимой задержки реального USB/ADC. Неудачный первый пакет был связан с fixture, повторно использовавшим открытый immutable ignition-файл; исправлено создание свежего окна, защита профиля файла сохранена.

Существенных незакрытых дефектов в заявленной области после recheck не найдено. Остаётся небольшое ограничение воспроизводимости: **source.zip содержит host и документы, но не `hardware/v2-input`** — таков явный pathspec упаковочного рецепта. Для P0 нужен checkout указанного Git commit; source.zip нельзя представлять полным аппаратным комплектом. Это не мешает воспроизведению приложения и не требует новой сборки принятого EXE.

## Аппаратные и эксплуатационные границы

P0 сохраняет различие U_ADC/U_CH1/напряжения источника датчика, DC-связь измерительного тракта, нагрузку кабеля/датчика и отсутствие пересчёта в кВ. Номинальный `a,b` не назначается текущей плате. Диапазоны и ФНЧ получены для условного питания ±15 В; имеющийся один ЛБП 0…20 В это питание не обеспечивает. Новый вариант DC/DC — кандидат для изучения, а не выбранная покупка или готовая схема питания.

Открыты защита при отключении/несимметричном появлении шин, обратное питание ADC, допустимая энергия, фактические утечки/ёмкости/полоса/восстановление, точность и калибровка. При номинальных 50 kS/s и расчётном ФНЧ около 3 кГц точный быстрый пик пробоя не обещается. Низковольтная проверка, датчик, зажигание и автомобиль требуют отдельных свидетельств. Сообщённая маркировка STM32F103C8T6 не заменяет независимую идентификацию платы/MCU.

Опубликованный кандидат PR 216 прочитан как источник последующей работы. Его статус — `DIAGNOSTIC_LINK_ONLY_NOT_QUALIFIED`, имя образа содержит `DIAGNOSTIC_UNQUALIFIED_NEVER_FLASH`. Условные доказательства stack/ABI точного опубликованного ELF существуют, но не переносятся на другой rebuild/плату. Unknown produced_end, реальные сроки обслуживания DMA/USB, quiescence/Stop, питание и разрешение конкретного образа ещё открыты. В этой итерации отсутствует физический COM-путь нового потока.

Не подтверждены: чистая Windows без среды разработчика, другие ОС/DPI, запись до полного лимита 64 MiB, реальный USB throughput/частота ADC, отключение питания носителя во время экспорта, общественная дистрибуция с полной проверкой зависимостей. Устаревший/отсутствующий companion не восстанавливает имя/профиль автоматически; явный выход без контекста оставляет raw, но отказывается от этого снимка. Отменяемый файловый просмотр и реально завершаемый writer имеют разные гарантии.
