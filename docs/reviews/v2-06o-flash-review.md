## Обязательные условия исполнения

1. Root непосредственно перед Flash подтверждает ожидаемые COM6/PNP без ошибки, единственный ST-Link с прежним SN и отсутствие владельцев приложения/захвата/CLI. Сохранённый inventory до backup не считается текущим. Питание остаётся только от USB, без3,3В ST-Link, PA0 пустой.
2. Ровно один program с verify, затем независимый полный readback44 212 байт. Только побайтное равенство допускает один Reset/Run. Перед исполнением проверяются exact plan admission и все pins. Расхождение или ошибка останавливают процедуру.
3. После **этого** SH Reset root получает новый фактический ответ пользователя о USB-переподключении, связывает его с хешем reset log и хронологией. Раннее «готово» до Flash не подходит. Перед COM open проверяется актуальный inventory.
4. Единственный сеанс150000/10 сохранённых бит, mode5, maxDATA1024, запрос Record30с, START≤1.50/100 отсутствуют. Отказ заканчивает план; повтор/Reset/rollback не автоматические.
5. Во время активного COM нет SWD/Halt. После закрытия owner выполняется offline проверка wire/nonce/generation/индексов/CRC/raw/Open и согласованного END/STOP_ACK. Только затем разрешены две136B, две64B и stopped TIM3/ADC/DMA/RCC. Timeout/нет closed-owner или согласованного terminal запрещает `root_read_closed`; не считать убийство процесса подтверждённым Stop.
6. Подтверждения actual replug, отсутствия внешнего SWD/Halt и времени действий — факты оператора с логами, а не следствие булевых полей helper. Сохранить фактическую длительность. Timeout65с сам по себе не доказывает интервал меньше оборота DWT32 при72МГц; при неизвестной валидности/оборотах не интерпретировать nominal timing. Cap64B ограничивает наблюдение, не захват.
7. Для ограниченного физического PASS нужны фактические30с без source fault/gap, normal END/ACK, raw/CRC/Open и подтверждённая остановка. Валидная диагностика либо сохранённый неполный prefix не заменяют этот результат.
