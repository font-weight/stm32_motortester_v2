## Лично проверенные основания

Среда: текущая Windows 10, локальный Git и Python среды проекта. Чтение
Git через `git ls-tree -r`, SHA-256 и Git blob SHA-1 через `hashlib`,
ELF32 little-endian через `struct`; повторная компиляция и исполнение
анализатора критиком не выполнялись.

1. Все **247** файлов извлечённого `source/firmware` совпали с Git blob OID
   указанного опубликованного commit: отсутствующих файлов и расхождений нет.
   Дополнительно независимо проверены **566** записей хешей входов,
   зависимостей и объектов manifest — без ошибок. SHA всех BIN/ELF/HEX,
   map/dis/nm/`.su` и самого static report совпали.
2. Шесть результатов двух отдельных сборок `v5-fw-03` и `v5-fw-04`
   лично сопоставлены побайтно: ELF, BIN, HEX, map, disassembly и nm одинаковы.
   Прочитана квитанция `build/v5-fw-04/reproducibility.json`.
   Это воспроизводимость данного Windows-рецепта, не герметичность всей ОС.
3. BIN независимо восстановлен из файловых `PT_LOAD` сегментов ELF и совпал
   полностью. Flash: `0x08000000..0x080083e4`; начальные MSP=`0x20005000`,
   Reset vector=`0x0800821d`. `.data`=128, `.bss`=9108 байт;
   статический конец=`0x20002414`, StackLimit=`0x20003000`,
   StackTop=`0x20005000`. Между статическими данными и резервом стека
   остаётся 3052 байта. Использование памяти не требует сообщённых
   программатором дополнительных 64 КиБ Flash.

## Граница разрешённого опыта

Допускается основной агентом загрузить **только указанный BIN** на ту же
плату через проверенный ST-Link, выполнить отдельный readback и system
reset, затем ограниченный 15-секундный транспортный опыт по плану.
Основания подключения: пользователь сообщил пустой A0 и питание только
от USB платы; ST-Link не питает её выводом 3,3 В. Не менять проводку и
не подключать внешние уровни, датчик, катушку или автомобиль.

Обязательны проверка текущих SHA и единственного ожидаемого ST-Link
перед записью, отказ при другой плате/образе, отсутствие mass erase,
изменения option bytes и защиты чтения. После программирования требуется
отдельный readback ровно 33764 байт с совпадением SHA. Неподтверждённый
readback не заменяется совпавшим HELLO build. Новый запуск выполняется
через системный Reset/Run, не через произвольную установку PC.

START не повторяется автоматически. Отказ запуска, неподтверждённая
идентичность или необходимость неготового исправления ведут к сохранению
свидетельств и возврату по плану: запись проверенной 64-КиБ копии,
отдельный readback с SHA, Reset/Run и прежний HELLO/GET_CAPS без захвата.
Если SWD недоступен, дальнейшие изменения питания/option bytes автоматически
не выполняются.

Два RAM-чтения диагностики допустимы **после** окончания приёма и закрытия COM.
Символ данного ELF: `mt_stream_diagnostics=0x2000238c`, размер `0x88`/136 байт.
Для заявления о замороженной записи нужны одинаковые байты, правильные
magic/version/bytes/build, `phase=3`, `final_hardware_off=1`,
`final_adc_owned=0` и ADC STOPPED по enum той же базы. Иное значение
сохраняется как отказ/неподтверждённая остановка, без удобного переобозначения.

Отдельный опыт физического отключения USB допускается после успешного
короткого опыта и **нового system reset**: диагностическая запись обслуживает
лишь первую попытку за boot. Он выполняется с участием пользователя,
сохранением префикса и фактического отсутствия END. Его результат не
предрешён этим допуском.

## Остаточные ограничения и замечания

- Не подтверждены физические HSE/VDDA/Fs, аналоговый тракт и калибровка.
  Сообщение ST-Link о 128 КиБ/ID не доказывает маркировку или подлинность MCU.
  Ранее наблюдённый HSI/default RCC и Windows error 31 полностью не объяснены;
  последующее восстановление прежнего соединения не переписывает эту историю.
- 1 мс transaction bound — предварительный параметр, не WCET. PRIMASK
  bracket, общий USB/ADC service относительно 2560 мкс и Stop budget
  предстоит наблюдать/квалифицировать отдельно. Отсутствие этих измерений
  не блокирует именно первый короткий диагностический опыт с пустым входом.
  Оно блокирует утверждения о гарантированной непрерывности и сроках.
- Стек проверен условной статической моделью, не физическим high-water.
  DWT modulo, counts/flags, отсутствие halt и длительность опыта ограничивают
  интерпретацию диагностики; максимум наблюдения не становится WCET.
- Нормальный END этого образа оставляет `produced_known=0`; tail/loss unknown
  сохраняются. Успешная запись принятого префикса не доказывает отсутствие
  потерянных преобразований АЦП.
- Повторное подключение в той же панели после штатного Disconnect передано
  автору host как отдельный UX/lifecycle вопрос. Для принятого probe создаётся
  один свежий owner и выполняется один опыт; итоговый GUI/пакет проверяется
  отдельно. Этот отчёт не скрывает незавершённую UI-приёмку.
- Общий план `streaming-v2.md` ещё содержит этап будущего низковольтного опыта.
  Текущий отдельный допуск определяется `v2-stream-trial.md` и настоящим
  отчётом; расширять его до низковольтного измерения нельзя.
