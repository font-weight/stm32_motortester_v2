## Причина и проверенное поведение

Пользователь подтвердил соединение COM6, график и Save/Open, затем сообщил, что закрытие требует сохранения неполных данных в JSON. Безусловная блокировка при `pending_incomplete` подтверждается исходным кодом базы. Причина появления фрагмента именно в пользовательском сеансе неизвестна: его raw и журнал не получены. Отдельное незавершённое окно само по себе не означает повреждение сохранённой полной `.mtv2`.

Проверена дельта `device.py`, `device_ui.py`, `gui.py`, адресных тестов и упаковочного сценария:

| Требование | Результат чтения кода и свидетельств |
|---|---|
| Три явных варианта | Диалог предлагает «Сохранить JSON», «Закрыть без JSON», «Отмена». Default и Escape — отмена; неизвестный результат диалога также трактуется как отмена. Повторный Close во время модального вопроса не создаёт вложенный вопрос. |
| Сохранение перед закрытием | Сохраняется конкретный результат с его исходным контекстом. Закрытие продолжается только после успешной записи и принятого ACK. Отмена пути и ошибка записи оставляют приложение и pending; старый путь кнопкой панели сохранён. |
| Явный отказ | `discard_incomplete` принимает только текущий объект по identity. Нет общего флага разрешения потери любых данных, удаления файлов или изменения raw. После завершения worker освобождение локальное; при живом worker требуется принятие его ACK. |
| Поздние данные и shutdown | Квитанция принятого сохранения/отказа относится к точному объекту и переживает отмену очереди ACK во время shutdown. `_finished` освобождает только тот же объект. Новое окно сбрасывает квитанцию и требует отдельного решения, даже если его содержимое равно старому. |
| Сохранённые записи и прежние ограничения | Полная сохранённая `.mtv2` остаётся побайтно неизменной. Защита полного несохранённого результата, занятости файловой операцией и завершения worker сохранена. Решение об отказе от JSON не обходит Stop/reset/recovery. Калибровка, единицы, wire и firmware этим изменением не затронуты. |

Принципиально различены отмена закрытия и восстановление соединения: после уже завершившегося worker «Отмена» оставляет окно программы и данные, но не возобновляет прежнее получение автоматически.

## Независимая сверка происхождения

Read-only сверка критика, без запуска приложения:

- Все **17** записей [SHA256SUMS.txt](../verification/v2-close/package/SHA256SUMS.txt) совпали с файлами исходной выходной папки `build/v3a1`, включая ZIP, source.zip, журналы и PNG.
- Все **17** сохранённых в `docs/verification/v2-close/package` свидетельств побайтно равны оригиналам. Для `build-manifest.json` оригинал находится внутри `dist/MotortesterV2`.
- Размер ZIP и его SHA совпали с указанными выше. Оба EXE внутри ZIP побайтно равны файлам в `dist` и в фактически проверенном каталоге «Проверка переноса».
- [Manifest](../verification/v2-close/package/build-manifest.json) внутри ZIP совпал с сохранённой копией; его source commit и SHA исходного архива согласованы с отчётом.
- ZIP-комментарий `source.zip` содержит точный commit. Все **10 изменённых файлов `host/`** в архиве сверены с этим commit: допустима только наблюдаемая конверсия LF/CRLF при `git archive` на Windows. Различий исполняемых файлов рабочей копии `host/` относительно проверенного commit нет.

Повторный аудит всех зависимостей и унаследованных сценариев не проводился: исправление не меняет их выбор или состав. Архивы остаются локальными; небольшие первичные свидетельства хранятся в репозитории.

## Замечания и их закрытие

Исходное ограничение UX — обязательный JSON при Close — заменено требуемым явным выбором. При предварительном чтении дополнительного дефекта реализации, требующего переписывания, не найдено.

**C-R1, P2 к полноте проверки:** первоначальный адресный случай не доказывал, что новое равное по значению окно не наследует старую квитанцию освобождения. Критик запросил именно эту границу. Автор дополнил существующий случай, сохранил [отдельный журнал](../verification/v2-close/adapter-02.log); assertions и сброс квитанции при новой identity проверены. **Закрыто.**

Данных о неудачных запусках данной итерации в представленных журналах нет; прежние неудачи V2-03 сохранены на своих местах и не переименованы в свидетельства V2-03a.

## Ограничения и следующий шаг

Новый физический COM-сеанс и причина неполноты пользовательского окна не установлены этим ревью. Не подтверждены калибровка CH1, допустимый DC-вход, измеренная Fs/полоса, зажигание, автомобиль, чистая Windows без установленного Python и подписанный публичный релиз. Отмена закрытия не гарантирует возобновление уже остановленного соединения.

Следующий пользовательский шаг — распаковать **новый** ZIP целиком и запустить `MotortesterV2.exe`. При закрытии выбрать «Закрыть без JSON», если отдельные незавершённые фрагменты не нужны; ранее сохранённую `.mtv2` это действие не меняет. «Сохранить JSON» сохраняет фрагменты перед выходом, «Отмена» оставляет приложение открытым. Настройка аппаратного входа остаётся отдельным этапом.
