## Начальные замечания — сохраняются как история

1. **R1 / P1 — DEMO зажигания не запускается.** `source.py:next_block` при фазе 0 вычисляет `0.4 + 2.25 + 0.65 = 3.3 В`; `DEMO_PROFILE.code` принимает максимум `4095*3.3/4096 = 3.2991943359375 В`. Поэтому первый блок `DemoSource("ignition")` вызывает V2Error, как и переключение профиля/`--profile ignition`. Исправление: синтетическая форма внутри определённого диапазона, без молчаливого clamp.
2. **R2 / P1 — GUI не открывает legacy MTCAP с неизвестной шкалой.** Корректный legacy reader сохраняет `threshold_v=None`; `_load_saved_controls` передаёт None в `Knob.set_value → float(None)`, а `_display` безусловно вызывает `threshold_line.setValue(None)`. Следует сохранять неизвестность, отключать недоступное отображение и не подставлять DEMO-порог.
3. **R3 / P1 — одиночный захват заканчивается до получения постистории.** `_tick` проверяет `event.end_index > candidate.end_index`, но `find_events` уже обрезал этот конец до доступной записи и выставил `right_truncated`. Поэтому, например, окно 200 мс захватывается после первого 50 мс блока, даже если будущие данные доступны. Нужен зафиксированный кандидат и ожидание необходимого конца; запросы длиннее ограниченного буфера должны иметь честные пределы/поведение.
4. **R4 / P1 — несохранённые данные могут быть заменены без защиты.** `arm_single` допускает повторный захват поверх `self.single` без подтверждения. Один `self.dirty` используется одновременно для single и completed: сохранение одного результата сбрасывает защиту другого. Нужны независимые состояния сохранения либо один явный защищённый документ. Проверка должна охватывать повторный single и сосуществование single/recording.
5. **R5 / P2 — сохранённые настройки показываются с DEMO-ограничениями.** `_load_saved_controls` загружает порог в диапазон 0…3.299 В, holdoff — 0….1 с, предысторию — 0…90%; формат допускает другие корректные значения. `Knob.set_value` молча ограничивает их, поэтому панель «Сохранённые параметры» может не соответствовать файлу. При возврате в live эти настройки также заменяют настройки текущего DEMO. Нужны точное представление snapshot и отдельное восстановление live controls.
6. **R6 / P2 — неверная проверка соседнего файла экспорта.** `_choose_path` проверяет `path.with_suffix(".json")`, тогда как `export_csv` создаёт `.csv.json`. При наличии только настоящего sidecar пользователь не получает корректное предложение замены; файл-хранилище затем отклоняет экспорт. Проверка должна использовать тот же путь, что и writer.

Указанные выводы получены чтением кода и проверяемыми арифметическими условиями; они не представлены как запущенные тесты. Автоанализ/перерисовка максимальной ограниченной записи выполняются в GUI-потоке: достаточность отзывчивости должна проверяться одним относящимся к сценарию smoke, а не широким набором производительности.

### Оставшиеся границы и следующий шаг

Реальный источник, firmware/native USB, непрерывность потока, DC-вход и калибровка/полоса не проверены и не входят в принятый результат. Не приняты Windows EXE/установщик, чистая машина без Python, полная DPI-матрица, стенд/автомобиль, автоматические стадии искры/диагностика/ML. MTREC остаётся в прежнем viewer; новый UI принимает MTV2 и legacy MTCAP с неизвестной шкалой. Пределы 2 млн отсчётов, окно single ≤1 с и синтетический контекст искры 5 мс сохраняются.

После документальной фиксации вердикта и публикации разрешённой ветки следующий шаг пользователя: запустить `run_v2.cmd`, выбрать профиль «Зажигание» и источник «ДЕМО · зажигание», выполнить запись → Stop → сохранить → открыть и сообщить замечания по своему экрану. Следующая ограниченная задача разработки — V2-02: пользовательская проверка интерфейса и самостоятельная Windows-упаковка. Аппаратные задачи ведутся отдельно.
