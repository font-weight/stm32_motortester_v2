## Что проверено в реализации

Положительный исход выделен узко: END reason=0, flags=3,
`produced_end=None`, ненулевой идентификатор текущего переданного STOP.
Существующие проверки поколения, конфигурации, префикса, CRC, sequence
и request ID сохранены. Сам END ещё не является успешным завершением:
до согласованного STOP_ACK остаются ожидание и deadline. Для записи
нужны также завершение владельца хранения и отсутствие иной ошибки.

Фаза `stopped unknown tail` даёт фразу
«Остановлено по команде · полнота хвоста неизвестна». Она не присваивает
произведённому концу или потерям ноль. В terminal остаются
`reason=stopped`, `failure=None`, неизвестные produced/loss;
`clean_stop=false` сохраняется при новом открытии и экспорте.
Старые файлы с прежним `source_failure/device_0` не переписываются
и не получают новую интерпретацию.

Отдельно прослежены flags4, реальная причина END, неверный/отсутствующий
ACK, ошибка хранения, прежний first fault и поздняя ошибка:
они не получают положительную фазу. Неизменяемый footer, уже выданный
до поздней ошибки, не переписывается; поздний отказ остаётся в состоянии
живого сеанса. Этот существующий предел формата не скрыт положительной
надписью живого UI.

Исключение для READY-close относится только к здоровому подготовленному
соединению без START, identity/session/storage и незавершённых команд.
Оно не очищает ранее возникший fault. Ошибки чтения и фактического
закрытия остаются видимыми; неуспешное закрытие сохраняет владение COM
до явного retry. Остановленный preview без writer отдельно проверен
по matching END/ACK и отсутствию ошибок.

| ID | Итог |
|---|---|
| R1, P2 из V2-05 | **Закрыто для новых сеансов:** штатный unknown-tail Stop отделён от ошибки только при matching ACK; intentional READY-close чистый. Положительный и отрицательные сценарии подтверждены; реальные ошибки чтения/close не скрыты. |

| Остаточная особенность UI | Технические сведения длинные и местами содержат имена протокольных полей. На 850×650 требуется прокрутка. Это не потеря данных и не блокер данной адресной правки; учитывается в C4. |

Старые записи сохраняют прежнее предупреждение. Новая надпись не
доказывает отсутствие пропусков АЦП, измеренную Fs или напряжение CH1.
Шкала физического входа остаётся unconfigured; служебные коды включаются
явно. Firmware V2S4 не менялась, а прежние аппаратные результаты не
объявляются новым испытанием этого EXE. Следующий пользовательский
повтор на COM6 ещё не получен.

Пакет — неподписанный локальный технический кандидат; чистая машина
и публичный выпуск не проверены. Существующие пределы лицензирования
и соответствующих исходников зависимостей не переоценивались этой
узкой правкой. Новых обязательных свидетельств для её программной
области не недостаёт.
