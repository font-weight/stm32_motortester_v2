## Обязательные пределы интерпретации

- Положительные DATA-байты означают известный приём FIFO callback до post-write проверки, не доставку USB, не committed prefix и не отсутствие потерь. Неизвестные записи не заменяются нулевым объёмом.
- Сумма prepare включает IRQ, наблюдатель и вызовы cached/EMPTY; открытая подготовка исключается с явными флагами. После CLOSING никакие поздние эпилоги не меняют снимок. Начальный и конечный участки без положительного прогресса входят в gap.
- Cap250мс проверяется в checkpoint; фактическое время/overshoot сохранено. Это ограничение наблюдения, не остановка ADC. Позднейший после cap отказ не становится первым событием этого снимка.
- ACTIVE ADC-fail фиксируется до quiesce, с недоступными core-полями. До ACTIVE вызов с NULL не может привязать EMPTY bank: при отказе START остаётся NO_START и отдельная исходная причина в legacy136. Это не полная трасса всех pre-start событий.
- Нужны свежий boot, два одинаковых frozen64 и136, одинаковые nonce/generation/build, закреплённый readback образа и отдельная аппаратная хронология. Декодер не аутентифицирует эти внешние факты сам.
- DWT-интервалы условны: без Halt/Reset и короче оборота32бит, при номинальных72МГц. Количественное влияние observer физически не измерено; выводы о доле CPU, калибровке или единственной причине переполнения недопустимы. Остаток28 байт требует нового resource review при любом росте static.
