## Результат разбора

1. **F103 FIFO-путь учтён.** При `CFG_TUD_EDPT_DEDICATED_HWFIFO=1` передача идёт через `xfer->ff`; отдельный software EP staging384 не выделяется. Допуск проверяет исключительный выбор buffer либо FIFO, неизменность указателей, total и ожидаемого queued-прогресса. Append не расширяет опубликованный transfer. Draft02, допускавший только buffer, исправлен до final; native отдельно исполняет FIFO-путь.
2. **Продолжение ограничено.** Foreground grant даёт бюджет6; ISR сначала удерживает HP/LP NVIC. Продолжение возможно только для промежуточного IN0x82 bulk с maxpacket64 и total≤384. Final, OUT/SETUP, другой endpoint, lifecycle/error, неверный прогресс и исчерпанный бюджет не получают автоматического продолжения. Native включает short/ZLP/64/65/307/384/385, budget, события до/во время обработки и отрицательный ISR-hold контроль.
3. **500 мкс — условие следующего разрешения.** Проверяются TIM2 clock/reset/CR1/PSC/ARR и elapsed<500 от grant;499/500 и16-битный wrap исполняются в модели. Это не верхняя граница длительности последнего ISR или всей серии и не доказанный WCET. Полные пропущенные обороты16-битного таймера этим guard не обнаруживаются: основная TIME-проверка и отсутствие debugger halt остаются предпосылками. Документы явно сохраняют эти ограничения.
4. **Принятый префикс сохраняется.** Native исполняет реальные core serialization/Stop/END, полный DATA одним write, partial/zero/unknown acceptance и live_write384/385. SIZE_MAX вызывает fencing; частичное принятие не объявляет raw-префикс полным. Реальный TinyUSB FIFO384 проверен на wrap, ёмкость, опубликованную длину, дописывание77 байт, short/full/ZLP. В том же core-запуске прошли прежние DMA1024/half512→DATA128, Stop-tail1023, отказ на каждом split chunk и CEN5/6 мкс.
5. **Ресурсы помещаются.** Text36120 + data128 =36248 байт Flash. Data128 + bss11212 + stack reserve8192 =19532 из20480 байт SRAM, остаётся948 байт вне резервов. Рост относительно V2S5 —328 байт, не два буфера по320. Условная статическая граница стека5924, с выравниванием5928, меньше8192. Это анализ точного ELF при описанной модели вызовов/IRQ, не измеренный high-water/WCET.
6. **Host wire совместим.** DATA128, CAPS200000/1 и формат не менялись; observed build на host допускает uint32 без whitelist V2S5. Повторная упаковка программы ради build ID не требуется. Физическая совместимость новой прошивки с Windows USB проверяется отдельно.

Промежуточные отказы сохранены: compile01 signedness; burst01 WKUP без SUSP в fixture; core01 порядок TinyUSB headers; draft02 buffer-only. Исправления подтверждены финальными источниками/моделями. Build03→04 изменил README/receipt при равных C/H и образах. Старый физический отказ и старые ограничения host-тестов не объявляются исправленными этими native PASS.

## Замечания и следующий допуск

Открытых P0/P1 **в согласованном программном результате V2-06b** не выявлено. Вне него остаётся **P1: физические200 kS/s не приняты** — V2S5 остановилась после1152 кодов до Record. Переполнение firmware-очереди установлено, единственный первичный предел throughput пока не локализован. Патч — обоснованный кандидат, а не доказанное устранение аппаратного отказа. Неизвестны реальные IRQ/ADC сроки, средняя скорость USB, точность Fs и аналоговый отклик. Native seams не исполняют полную CDC/PMA/USB PHY реализацию.

Для нового отдельного допуска: `mt_stream_diagnostics=0x20002BC4`,136 байт; прежний адрес V2S5 `0x20002A7C` для V2S6 неверен. Адрес/размер сверены с exact image.nm; MSP из BIN `0x20005000`, reset vector `0x080087D9`. Новый план должен сохранить readback/rollback, проверить build/Fs до START, провести один ограниченный опыт и отдельно оценить raw/Stop/Open/диагностику. Допуск V2S5 не переносится. Пропущенные в V2-06a чтения TIM3_ARR/RCC enable следует явно включить в новый план без чтения ADC_DR. Этот отчёт не заменяет аппаратный допуск.
