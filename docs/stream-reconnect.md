# V2-14 — новый сеанс STM32 на той же странице

## Порядок работы

Для изменения уровня, направления, паузы поиска или предыстории нажмите
«Остановить» и дождитесь завершения записи/сохранения контекста. Поля справа
снова доступны; нажмите «Применить поиск». Параметры относятся к следующему
запуску и не меняют закончившуюся запись. Во время live/record они фиксированы.

После Stop или просмотра файла выберите частоту приёма, если её надо изменить,
и нажмите **«Переподключить COM6»** в верхней строке (имя зависит от выбранного
порта). Приложение завершит старое соединение и проверит новое. При READY
откроются параметры нового запуска; нажмите **«Живой поток»** отдельно.
Выходить через «Остановить и вернуться» не требуется. Если порт лишь
подключён, но захват ещё не запускался, сначала можно нажать «Отключить».
Смену самого COM-порта по-прежнему выполняют через исходный выбор порта.

У открытого `.mtstream` крутилки меняют только поиск в файле. Для настройки
следующего измерения сначала переподключитесь. Сохранённые параметры `.mtshot`
не редактируются. Последние применённые live-настройки возвращаются после
согласования той же частоты/разрядности; другая Fs/bits сбрасывает их с
сообщением. Файловые overrides не становятся настройками нового измерения.
Временная ошибка HELLO/CAPS не стирает ожидающие live-настройки: повторное
подключение сохраняет их до успешного согласования Fs/bits.

Предыдущие файлы не переписываются. Готовая копия одиночного захвата остаётся
доступна для сохранения; перед новым подключением несохранённый кадр требует
явного решения. Отмена оставляет прежний сеанс/кадр. Файл остаётся на экране
до успешного READY; при неудачном подключении сохраняется возможность его
просмотра. Переподключение само по себе не запускает приём и не прошивает плату.

## Владельцы и отказы

Страница, файловый worker, viewer, курсоры и редактор сохраняются. Прежний
bridge завершается через обычный shutdown. Только его finished (join
receiver/disk/display и подтверждённое закрытие OS handle) допускает создание
нового bridge. Shared serial lease остаётся у этой же страницы; второй
владелец не получает порт между этапами. Старые state/live/error/saved/finished
сигналы проверяются по identity bridge, а не повторяемому счётчику revision.

Незавершённое сохранение/ошибка companion блокируют переподключение. Ошибка
закрытия порта оставляет старого владельца: кнопка «Повторить закрытие порта»
повторяет только cleanup; новый Connect ждёт. Закрытие страницы во время
этого ожидания имеет приоритет: нового bridge/автозапуска быть не должно.
Во время активной записи/ожидания файлового диалога новая попытка запрещена.
Изменения в аппаратном протоколе, физический reset USB и исправление драйвера
Windows сюда не входят; новое подключение не гарантирует устранения их ошибок.

Критерии программной приёмки: Stop/file/reconnect/READY без START, повторный
live с отдельным draft, неизменные хеши исходных файлов, тот же widget/viewer,
отмена dirty, блокировка metadata failure/close failure, пять запоздавших
сигналов старого bridge, закрытие во время restart, native/frozen и PNG.
Фактические результаты — progress и отчёт независимого критика.
