# Формат записи и Python API V2

Документ описывает реализацию первой итерации V2. Происхождение исходников и
текущий статус — в [README проекта](../../README.md) и
[журнале прогресса](../../docs/progress.md). Программные проверки не подтверждают
точность, полосу или готовность физического входа.

## Чтение без интерфейса

Команды выполняются из `host/`; PySide6, pyqtgraph и устройство не нужны:

```powershell
python -m motortester.v2.inspect запись.mtv2
python -m motortester.v2.inspect запись.mtv2 --start-index 10000 --stop-index 20000 --csv участок.csv
```

Также читаются унаследованные `.mtcap`. Команда выводит JSON: происхождение,
снимок профиля входа, фактическое число отсчётов, доступные границы, разрывы и
вычисленные показатели. Границы — абсолютные индексы исходного источника;
правая граница исключается. Можно задать одну границу; вторая будет взята из
записи. Недоступные края отмечаются как обрезанные, пропуски не заполняются.
CSV и JSON создаются рядом; существующие файлы не перезаписываются.

```python
from motortester.v2.core import load, analyze, cursor_measurement, export_csv

recording = load("запись.mtv2")
segment = recording.slice(10000, 20000)  # [start, stop), source sample indices
measurements = analyze(segment)
for sample_index, time_s, adc_code in segment.iter_samples():
    voltage_v = (
        segment.input_profile.voltage(adc_code)
        if segment.input_profile.configured else None
    )
    # time_s = sample_index / sample_rate_hz, включая пропущенное время.
cursors = cursor_measurement(segment, 0.22, 0.24)
export_csv("участок.csv", segment)
```

Внутренние единицы — секунды и вольты на разъёме CH1. Преобразование едино:
`U_CH1 = a × code + b`; отрицательный `a` учитывается в экстремумах и фронте.
Шкала `unconfigured` не выдаёт напряжений; в JSON показателей и курсоров они
равны `null`, в CSV поле `voltage_v` пустое. Значение курсора выбирается по
ближайшему исходному отсчёту; его фактическое время доступно в
`sample_time_a_s` / `sample_time_b_s`. Внутри пропуска значения нет.

`find_events(recording, settings=None)` возвращает кандидатов пересечения
порога с программной паузой запуска. Контекст задаётся `window_s` и
`pretrigger_fraction`; `left_truncated`, `right_truncated`,
`missing_context` и `clipping` описывают ограничения. Это не идентификация
цилиндра и не автоматическое измерение времени горения.

В профиле «Осциллограф» `analyze` измеряет период по восходящим пересечениям
середины между наблюдаемыми минимумом и максимумом, без паузы запуска.
Результат не зависит от порога, фронта и holdoff захвата. Это простой метод
для достаточно регулярных сигналов, а не доказательство основной частоты
любой сложной формы. В профиле «Зажигание» возвращается интервал/частота
событий по фактическому порогу, фронту и паузе запуска; это не RPM.
Частота/период появляются только при трёх согласованных интервалах: разброс не более
максимума из 5% медианного интервала и двух периодов выборки; при разрывах
или недостаточных данных они неизвестны.

## Основной файл `.mtv2`

Версия формата — 2. Запись — неизменяемый снимок одного CH1. Внутри текущего
сеанса фиксированы частота выборки и профиль входа; изменение тракта требует
другого сеанса. Профиль интерфейса (`oscilloscope`/`ignition`) независим от
электрического профиля. Происхождение `demo` или `device` сохраняется после
открытия; чтение файла не меняет его на «аппаратное».

| Часть | Содержание |
|---|---|
| Заголовок, 16 байт | `<8sII`: magic `MTV2RAW\0`, размер JSON, число отсчётов |
| JSON, UTF-8 | `format_version=2`, `sample_encoding=uint16-le`, `adc_bits=12`, метаданные ниже |
| Исходные данные | Последовательность блоков uint16 little-endian, коды строго 0…4095 |
| 32 байта в конце | SHA-256 всех предыдущих байтов; защита от повреждения, не подпись автора |

В JSON находятся `channels` (сейчас один элемент `CH1`, пользовательское имя
и полный `input_profile`), снимок `capture_settings`, `session_id`, UTC-дата,
источник, версии ПО/прошивки/протокола, временная основа и общие флаги качества.
Для каждого блока сохранены `start_index`, `sample_rate_hz`, `sample_count`,
`quality_flags`, `gap_before`. Неизвестные поля имеют значение `null`, а не
придуманные коэффициенты или версии.

Профиль входа содержит `a`, `b`, состояние шкалы, идентификаторы входа/тракта/
диапазона, DC/AC, происхождение коэффициентов, сведения о калибровке, точку
измерения и землю, описание датчика, известные Vref, полосу и линейный диапазон.
Имя датчика не является коэффициентом. DEMO явно использует синтетический
профиль `demo-3v3-12bit-v1`: `a=3.3/4096`, `b=0`; это не профиль физической платы.

Лимиты чтения/записи: 2 000 000 отсчётов, 4096 блоков, 1 MiB метаданных.
При 50 кГц это 40 секунд сохранённых DEMO-отсчётов; разрывы могут увеличить
полную временную длительность. Перекрывающиеся блоки, другая разрядность,
повреждённый hash, неподдерживаемая версия и лишние/отсутствующие поля
отклоняются. Основной файл сохраняется атомарно через прежний `atomic_write`.

## Совместимость и экспорт

Старый reader `.mtcap` версии 1 сохранён. V2 проверяет его файл штатным
декодером, переносит исходные коды и известные метаданные, устанавливает
`legacy_format=mtcap-v1`, `legacy_sequence` и шкалу `unconfigured`.
Порог старого захвата сохраняется в `hardware_threshold_code`, а
`threshold_v=null`: неизвестный тракт не получает синтетический пересчёт.
Оригинальный `.mtcap` не меняется. Старое приложение не читает `.mtv2`.

Экспорт создаёт `имя.csv` и `имя.csv.json`. Столбцы CSV:
`sample_index,time_s,adc_code,voltage_v,block_index,gap_before`.
Время остаётся абсолютным относительно нулевого индекса источника; строки
после пропуска не сдвигаются назад. JSON сохраняет метаданные исходной записи,
границы выбранных блоков, список разрывов и `csv_sha256`.

CSV/JSON — два отдельных файла. После прерванной перезаписи их несоответствие
определяется по `csv_sha256`; для восстановления основным форматом служит
атомарный `.mtv2`. CLI намеренно не перезаписывает существующий экспорт.
Результаты анализа возвращаются отдельно и не заменяют raw-отсчёты.
