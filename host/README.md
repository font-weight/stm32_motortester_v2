# Приложение Мотортестера V2

Новый интерфейс: один CH1, профили «Осциллограф»/«Зажигание», шкала напряжения на разъёме В/мВ и явный DEMO. Фактические возможности, выполненные проверки и ограничения текущей итерации — в [прогрессе V2](../docs/progress.md). Старый host-код сохранён как основа; его прежние отчёты не подтверждают новую композицию.

## Непрерывный поток

V2-06d принимает согласованные профили wire 0.2 **50/100/200 kS/s** и показывает
полученную Fs. Файлы и CSV используют её для времени (20/10/5 мкс на отсчёт).
Установка нового приложения не меняет частоту платы: каждый профиль требует
соответствующего образа. V2S4 —50k, новый кандидат V2S7 —100k; фактическая
аппаратная проверка каждого образа указана только в progress.
[Порядок перехода и возврата](../docs/streaming-200ksps.md).

Для платы с проверенной V2/wire 0.2 из progress: **«Непрерывный приём · STM32»** → выбрать COM →
«Подключить» → дождаться готовности → явно включить служебные коды →
«Живой поток» → «Начать запись» → выбрать новое имя → «Остановить» →
«Открыть запись». Connect не запускает АЦП. Оконный wire 0.1 несовместим;
смена firmware выполняется отдельно, приложение не прошивает плату.
После завершения закройте окно перед следующим подключением.
Если запрошен reset, переподключите USB платы.
Штатный Stop сохраняет префикс, но не подтверждает полноту произведённого
хвоста. После согласованных END/ACK: **«Остановлено по команде · полнота хвоста
неизвестна»**. Этот смысл сохраняется при открытии и экспорте файла.
Неподтверждённая остановка и ошибки по-прежнему дают «Поток прерван».
Прежние записи сохраняют свою исходную классификацию.

Запуск прежний: из корня `run_v2.cmd` либо из `host`
`..\.venv\Scripts\python.exe -m motortester.v2`.
Кнопка **«Непрерывный приём · ДЕМО»** открывает отдельное окно. Выберите профиль
в главном окне до его открытия; в потоке включите служебные коды явно.
Живой поток → запись в новый `.mtstream` → пауза просмотра → Stop →
открытие файла → CSV + JSON. Имя и профиль сохраняются в соседнем `.v2.json`
с хешем журнала: переносите оба файла. Существующие файлы не перезаписываются.
Неизвестная шкала означает отсутствие пересчёта в В/мВ.

Источник кнопки ДЕМО программный, 50 kS/s номинально. Оконный STM32 остаётся
отдельным. Номинальное время и получение raw не подтверждают электрическую точность:
[границы и продолжение](../docs/streaming-v2.md). Выполненные проверки и
проверенный пакет — только в [progress](../docs/progress.md).

## Переносимый пакет V2

V2-02 упаковывает принятый интерфейс после отзыва пользователя «все удобно». Результаты сборки, её проверок и местонахождение готового комплекта хранятся в [progress.md](../docs/progress.md).

В распакованной папке `MotortesterV2` находятся `MotortesterV2.exe` (окно), `MotortesterV2Inspect.exe` (чтение/экспорт в консоли) и общий `_internal`. Python отдельно устанавливать не требуется. Сохраняйте и переносите всю папку, а не один EXE; файлы записей пользователь сохраняет в выбранном месте. Порядок запуска — [README_PORTABLE_RU.txt](packaging/v2/README_PORTABLE_RU.txt).

Кандидат пока не подписан, не является готовым публичным релизом и не подтверждает запуск на чистой Windows без Python. Унаследованный [аудит уведомлений/исходников зависимостей](packaging/LICENSE-REVIEW.md) сохраняет открытые пункты; создание ZIP их автоматически не закрывает.

## Запуск из исходников

```powershell

cd host
```

Повторный запуск из корня: `run_v2.cmd`. Используется `.venv` в корне, а не в `host/`. Закреплённые зависимости — [requirements-gui.txt](requirements-gui.txt). Среда этой итерации: Windows 10 build 19045, Python 3.14.7, Qt 6.12, pyqtgraph 0.14. Скриншот, результаты целевых проверок и наличие готового EXE перечислены в progress. Историческая упаковка ниже относится к прежнему GUI и не является автоматически пакетом V2.

ДЕМО не требует платы. В V2-03 физический источник подключается отдельным оконным адаптером; неизвестный вход остаётся `unconfigured`, калибровка не подставляется. Фактические результаты интеграции и версия нового EXE — в progress. Наследованные `python -m motortester` и `python -m motortester.gui` остаются старыми инструментами, новый UI запускается через `motortester.v2`.

## STM32: сначала совместимость, затем одно окно

Четвёртый пункт списка источников открывает панель «STM32 · подключение». Выберите COM и нажмите подключение: выполняются только HELLO/CAPS, без ARM. После READY запускать захват нужно отдельной кнопкой. Auto повторяет окна, Single ждёт одно событие, Stop завершает захват через существующий механизм подтверждения. Не подключайте новый внешний сигнал для первого опыта со связью.

Без известного входного тракта основной экран сообщает «Шкала напряжения не настроена». Явный флажок служебного просмотра включает график **кодов ADC**, без В/мВ и ΔU. Аппаратный порог задаётся отдельно в кодах 1…4094; предыстория — только объявленные 0/512/1024 отсчёта (0/25/50%). Аппаратного holdoff в wire 0.1 нет.

После получения окна нажмите Stop и сохраните одно полное окно как `.mtv2`; экспорт создаст CSV с пустым `voltage_v` и `.csv.json`. Неполные фрагменты сохраняются отдельным диагностическим JSON, не дополняются нулями. Непрерывный Record для устройства отключён: промежутки между окнами неизвестны и не склеиваются в временную шкалу.

При закрытии с несохранённым неполным окном V2-03a предлагает **«Сохранить JSON»**, **«Закрыть без JSON»** или **«Отмена»** (по умолчанию). Успешное сохранение продолжает закрытие; отмена выбора файла или ошибка записи оставляет приложение открытым и фрагменты в памяти. Отказ касается только показанного неполного окна, а новое требует отдельного решения. Уже сохранённая `.mtv2` не изменяется. Этот выбор не отменяет проверки остановки устройства и рабочего потока; версия исправленного пакета и результаты — в progress.

Отключите устройство и выберите DEMO, чтобы вернуться к прежним примерам. При требовании сброса подтвердите только фактически выполненный reset/переподключение; открытие COM не доказывает сброс. Подробный [контракт V2-03](../docs/device-connection.md) описывает выбранные firmware/protocol, известное расхождение Stop и границы проверки.

## Работа с ДЕМО

1. Для обычного сигнала выберите профиль «Осциллограф» и источник «ДЕМО · синусоида» либо «ДЕМО · прямоугольный». Для импульсов выберите профиль «Зажигание» и отдельно «ДЕМО · зажигание». Переключатель профиля меняет инструменты/начальные настройки просмотра и поиска, но не подменяет источник, исходные отсчёты или коэффициенты входа.
2. Пауза просмотра останавливает обновление экрана. Получение данных и активная запись продолжаются. Недавний сигнал содержит 1 секунду отсчётов; известные пропуски увеличивают показанный временной интервал.
3. «Одиночный захват» / «Одна искра» ожидает программное событие по CH1 с предысторией; повторное нажатие отменяет ожидание. Для осциллографа окно равно десяти делениям выбранной развёртки, максимум 1 с (≤100 мс/дел); для зажигания контекст — 5 мс. Это ограничения программного DEMO-захвата, не возможности аппаратного триггера и не измеренное время горения.
4. «Начать запись» → «Остановить запись» сохраняет сеанс в памяти. Максимум — 2 000 000 отсчётов: 40 с данных при DEMO 50 кГц; при достижении предела запись завершается с причиной. Начало не перезаписывается. Кнопкой «ДЕМО · пропуск 100 мс» можно проверить явный разрыв.
5. После Stop доступны сохранение `.mtv2`, открытие, экспорт участка и, для профиля зажигания, переходы между кандидатами событий. Четыре видовых регулятора, курсоры и обзор управляют просмотром. Порог, пауза запуска, фронт и предыстория заблокированы на время записи/ожидания и при просмотре сохранённого захвата; показывается причина. Имя, источник и профиль также не меняют записанный снимок.

Переименование CH1 через карандаш сохраняет пользовательское имя для новых данных. Оно не переименовывает вход и не исправляет метаданные старого файла. Для возвращения к новым настройкам используйте живой просмотр. Все параметры аппаратного входа остаются отдельной задачей.

## Данные и чтение без окна

[API `motortester.v2.core`](motortester/v2/core.py) и [команда inspect](motortester/v2/inspect.py) доступны независимо от Qt. Собственный файл `.mtv2` хранит raw uint16-le с допустимыми кодами 12-битного ADC, блоки/индексы/время, имя CH1, настройки захвата и снимок входного профиля `a/b/state`. Версия формата — 2, сигнатура `MTV2RAW\0`, контроль целостности SHA-256. Смена текущей калибровки не меняет открытый снимок. Предел этой реализации — 2 000 000 отсчётов и 4096 блоков; это ресурсные пределы host, не характеристики платы. Точный контракт — [docs/v2-format.md](docs/v2-format.md).

Импорт MTCAP v1 сохраняет raw и происхождение, но ставит шкалу `unconfigured`: файл не знает внутреннего аналогового тракта. `.mtrec` в новом UI/inspect не поддерживается: открыть его можно прежним просмотрщиком `..\.venv\Scripts\python.exe -m motortester.gui` из `host/`. Унаследованные stream-форматы сохраняют свои отдельные читатели и договорённости. Не присваивать неизвестным файлам DEMO-калибровку.

Готовые команды из `host/`:

```powershell
..\.venv\Scripts\python.exe -m motortester.v2.inspect "запись.mtv2"
..\.venv\Scripts\python.exe -m motortester.v2.inspect "запись.mtv2" --csv "анализ.csv"
..\.venv\Scripts\python.exe -m motortester.v2.inspect "запись.mtv2" --start-index 10000 --stop-index 20000 --csv "участок.csv"
```

Команда выводит JSON с происхождением, снимком входа, границами/разрывами и измерениями. Начало/конец — абсолютные индексы источника, конец не включается; пропущенную границу можно опустить. Имена экспорта должны быть новыми. Для `.mtcap` используется та же команда, но `voltage_v` остаётся неизвестным.

Минимальный пример отдельного Python-скрипта, запускаемого из `host/`:

```python
from motortester.v2.core import load, export_csv

recording = load("session.mtv2")
print(recording.channel_name, recording.sample_count, recording.input_profile.state)
# Индексы исходного источника; конец участка исключающий, время не уплотняется.
part = recording.slice(recording.start_index, recording.end_index)
export_csv("analysis.csv", part)
```

`export_csv` создаёт CSV и соседний `analysis.csv.json`: исходный `adc_code`, `time_s`, `sample_index`, `voltage_v` только для известной шкалы, номер блока/причины разрывов и снимок метаданных. JSON содержит SHA256 CSV, чтобы обнаруживать несовпавшую пару. CSV/JSON — экспорт для анализа, основной файл записи `.mtv2` остаётся единым атомарно сохраняемым документом. По умолчанию API не перезаписывает существующие файлы.

Основные модули: `v2/input.py` — физические единицы/профиль; `data.py` — неизменяемые блоки/запись; `source.py` — DEMO; `device.py` — оконный адаптер существующего `AcquisitionBridge`; `analysis.py` — события/измерения; `storage.py` — файл/экспорт; `core.py` — публичный API. GUI и виджеты отделены от них. Внутренние расчёты напряжений используют В; при unconfigured напряжений нет, коды доступны только в служебном просмотре.

## Сборка V2 из чистого исходного состояния

Новый рецепт — `host/packaging/v2/build_windows.py`; старый `host/packaging/build_windows.py` собирает прежний интерфейс и для V2 не используется. Нужны Windows x64, CPython **3.14.7 x64**, Git и доступ к закреплённым wheels. Зависимости сборки закреплены по версиям и SHA-256; PyInstaller — **6.22.3**. Исходное состояние должно быть чистым и связано с точным Git commit.

Команда **из корня репозитория**:

```powershell
.\.venv\Scripts\python.exe host\packaging\v2\build_windows.py --output build\v2w
```

Для повторной сборки указать новую короткую выходную папку, например `build\v2w3`: длинный путь может превысить ограничения Windows при установке Qt. Рецепт не удаляет прежние результаты. В выходной папке ожидаются:

| Выход | Назначение |
|---|---|
| `MotortesterV2-windows-x64.zip` | Полная папка `MotortesterV2` с двумя EXE, `_internal`, инструкцией `README_RU.txt`, уведомлениями в `licenses/`, `LICENSE`, `LICENSE-REVIEW.md`, lock-файлом и `build-manifest.json` |
| `source.zip` | Связанные с исходной версией материалы приложения; не полный corresponding source сторонних библиотек |
| `SHA256SUMS.txt` | Контрольные суммы выходных архивов |
| `build.log`, `build-report.json` | Ход и результат сборки; manifest внутри пакета фиксирует происхождение |
| `frozen-smoke/`, `inspect-report.json` | Результаты ограниченной проверки собранных GUI/CLI; изображения и синтетические файлы |

Критерии этой итерации: сборка из чистого состояния; запуск обоих собранных EXE; DEMO обоих профилей и запись/открытие/экспорт; распаковка конечного ZIP и запуск после переноса в путь с кириллицей; согласованные manifest/хеши/source-архив и включённые уведомления. Точные результаты — в progress, наличие рецепта не означает PASS. Широкий исторический набор не нужен; упаковку на этой машине нельзя назвать испытанием чистой Windows без Python.

`licenses` и исходные аудиты сохраняют открытые вопросы точного состава сторонних компонентов, corresponding source/замены библиотек и условий выпуска. Сборка технического локального кандидата не является заключением об их полном выполнении. Публичный релиз, цифровая подпись и аппаратное подключение этой задачей не выполняются.

Проверять только затронутые функции: преобразование/отрицательный коэффициент/порог/насыщение, raw и шкалу после открытия, ошибочные записи, разрывы, состояния GUI. Команды фактически выполненного минимального набора — в progress. Скриншот реального окна не подтверждает точность/полосу входа. Windows-сборка, низковольтный опыт, зажигание и автомобиль — отдельные уровни доказательства.

# Мотортестер: кандидат захвата и просмотра

Кандидат приложения для просмотра записей и явного управления захватом; синтетический путь «событие эмулятора → исходный массив → `.mtcap` → повторное открытие → график» проверяется отдельно от физического измерения. Это часть приложения общего MVP, а не готовый USB-мотортестер. Задача: [HOST-001, issue #5](https://github.com/font-weight/stm32_motortester/issues/5); критерии: [checklist](reviews/HOST-001-acceptance-checklist.md).

Реализованы ядро без внешних зависимостей, явно обозначенная синтетическая демонстрация, версионированный файл с проверкой целостности, CSV/SVG и тёмное окно просмотра. GUI открывает/сохраняет `.mtcap`, экспортирует CSV и PNG-иллюстрацию текущего графика, показывает предупреждения и номинальные шкалы, поддерживает масштаб/сдвиг и два курсора. Офлайн-справка: [help.md](docs/help.md).

GUI соединён с ограниченным байтовым runtime и транспортом указанного COM-порта; доступны аналоговые Auto/Normal/Single и явные Старт/Стоп. Панель показывает принятые CAPS, объявленную сборку прошивки и причины отказа; неподдерживаемая проверенная wire-версия отличается от повреждённого кадра. Номер сборки не называется SemVer или идентификатором физического экземпляра. Исторический аналоговый контракт принят обеими сторонами на точных A/B-версиях; это не автоматическая приёмка новой композиции. Текущие источники, доказательства и незакрытые границы перечислены в [resumed-delivery.md](docs/resumed-delivery.md). Windows 10, реальный USB, точность шкал, низковольтное измерение и зажигание требуют отдельных испытаний.

Измеренные ширины кнопки и флажков исправлены в отдельном PR140; это требует нового Windows-прогона, даже после Linux-проверок. Более ранний PR124/run38223631395 прошёл 1177 тестов, PyInstaller и frozen serial/GUI, затем упал на архиве исходников. Ни один старый результат не принимается за проверку этой композиции или чистой Windows 10. История отказов сохранена в [windows-smoke.md](docs/windows-smoke.md) и [составе передачи](docs/resumed-delivery.md).

Для ядра и CLI сторонние пакеты не нужны:

```text
python -m unittest discover -s tests -p test_recording.py -v
python -m motortester demo demo-output
python -m scripts.check_first_path verification-output
```

Выходные папки должны быть новыми: команды не перезаписывают предыдущие результаты. `demo-output` содержит `.mtcap`, CSV и SVG, причём график строится после чтения файла с диска. `check_first_path` проверяет 20 синтетических окон и отдельный контрольный массив; это не 20 измерений LV-001. Фиксированная дата в его fixtures задана для повторяемости и не является временем наблюдения.

GUI, Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-gui.txt
.\.venv\Scripts\python.exe -m motortester.gui
```

GUI, Linux:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements-gui.txt
.venv/bin/python -m motortester.gui
```

В Linux необходима графическая сессия и системные библиотеки Qt. Для автоматической проверки без экрана можно использовать offscreen, который не проверяет настоящий Windows desktop:

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen .venv/bin/python -m motortester.gui --screenshot gui-smoke.png
```

`--screenshot` запускает настоящее окно Qt, создаёт синтетическую запись, сохраняет и снова загружает её, сохраняет изображение и завершает приложение. Это служебный smoke-сценарий, он отделён от пользовательского PNG-экспорта графика. Окончательные результаты проверок привязываются к точному SHA в `reviews/` и checkpoint задачи; наличие команды не означает её прохождения.

## Экспериментальный байтовый путь

Из `host/`, без сторонних зависимостей:

```sh
python -m motortester.wire_demo wire-output --windows 20 --chunk-size 97
```

Настоящие COBS/CRC байты синтетического источника проходят через накопитель и
сборщик окна, затем сохраняются в MTCAP, читаются снова и превращаются в CSV/SVG.
Все исходные коды сравниваются. Папка должна быть новой. Это программная
проверка отдельного draft CLI без USB/serial, handshake или физического измерения.

- [Байтовый codec и накопитель](docs/wire-adapter.md)
- [Полные и неполные окна](docs/window-receive.md)
- [Сквозной пример и его ограничения](docs/wire-demo.md)
- [Контроллер Normal/analog: команды, Stop и восстановление](docs/session-controller.md)

Контроллер соединён с GUI через ограниченный рабочий поток. «Подключение и захват» предоставляет явное соединение, Старт/Стоп и Auto/Normal/Single для одного аналогового канала профиля LV-001. При объявленной поддержке предыстории доступны 0/512/1024 отсчёта (0/25/50% окна); иначе доступна только нулевая предыстория. Выбор выключен без подтверждённых текущих CAPS и во время захвата. «Старт» и Record используют выбранную настройку; принятое значение показывается отдельно после CONFIG_ACK.

Последнее полученное состояние STATUS показано отдельно от фазы команд ПК: отсутствие сообщения, устаревание и отключение отмечаются явно. Это не независимая проверка физического состояния. CAPS скрываются при потере текущего сеанса; ошибки не исчезают при обычном обновлении состояния. Внешний запуск и управление отдельным стендом исключены из MVP. Новая программная композиция, чистая Windows 10, физическая предыстория и USB проверяются отдельно. См. [границы интеграции](docs/acquisition-integration.md), [историю версий и статусов](docs/resumed-delivery.md) и [справку](docs/help.md).

## Сборка кандидата Windows

На Windows x64 с CPython 3.13.16 x64 и Git, из чистого checkout:

```powershell
py -3.13 packaging\build_windows.py
```

Скрипт проверяет точную версию Python и архитектуру, создаёт отдельный venv, загружает закреплённые Windows wheels с проверкой SHA-256, выполняет тесты/синтетический сценарий, собирает PyInstaller onedir, проверяет запуск frozen-окна и создаёт переносимый ZIP. При ошибке сборка останавливается; предыдущая папка не удаляется. Для повтора указать новую папку:

```powershell
py -3.13 packaging\build_windows.py --output build\windows-x64-candidate-2
```

Ожидаемые выходы: `build/windows-x64-candidate/Motortester-windows-x64-candidate.zip`, `source.zip`, `SHA256SUMS.txt`, `frozen-window.png`, `build.log`, wheelhouse и manifest внутри пакета. Запускать `Motortester.exe` после распаковки всей папки; `_internal` необходим. Установка Python пользователю готового пакета не должна требоваться, но на чистой Windows 10 это ещё не проверено. Установщик, системные ассоциации и драйвер не добавляются.

Это воспроизводимая процедура с закреплёнными входами, а не обещание побитно одинаковых EXE/ZIP: время сборки и особенности платформы сохраняются в manifest. PyInstaller не делает Windows-сборку из Linux. Подробности лицензирования: [LICENSE-REVIEW.md](packaging/LICENSE-REVIEW.md).

Для отдельной серии LV-001 доступен [ограниченный headless-сборщик](docs/lv-collector.md): отдельное прогревочное окно, 20 явных попыток, исходные wire-метаданные и учёт отказов рядом с неизменным `.mtcap` v1. Это API с явно переданным транспортом и команда проверки сохранённой серии; управление серией через GUI и автоматическое открытие COM не добавлены. Программная проверка не заменяет физический LV-001.

Текущая композиция сохраняет все non-host файлы main `c4d4dc2` и точный host PR132 с непересекающимися изменениями PR140 (переносы подписей), PR139 (масштаб по отдельным осям и пределы просмотра), PR142 (закреплённые GNU-тексты уведомлений). Полные версии, хеши и ограничения: [resumed-delivery.md](docs/resumed-delivery.md). [current-delivery.md](docs/current-delivery.md) и его JSON оставлены без изменения как историческая запись построения PR130; они не описывают новый состав. Общий протокол и файл остаются wire 0.1/MTCAP v1; предложения record-now/wire 0.2 здесь не приняты.
